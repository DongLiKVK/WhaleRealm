# 鲸域 · 网站后台管理系统 设计文档

> 面向 whalerealm.top 的**独立**内容与运营后台。与站点前台的会员赞助后台（`/api/admin/membership` + `#/admin/sponsors`）互不相干：
> 那一套复用站点用户会话，这一套有**自己的账号、角色、会话和权限目录**。
>
> - 入口：`http://127.0.0.1:8777/admin/`（开发） / `https://whalerealm.top/admin/`（生产）
> - 代码：后端 `server/src/{schema-admin.sql,admin-db.js,admin-guard.js,routes/admin-*.js}`，前端 `admin/`
> - 契约：`docs/admin-api.md`（逐端点的字段级约定）
> - 验收：`qa/admin-e2e.mjs`（97 项，覆盖鉴权 / 2FA / 越权 / 审核 / 禁用 / 奖励 / 日志 / CSV）+ `qa/admin-smoke.mjs`（19 项生产只读冒烟，支持 TOTP）

---

## 1. 目标与边界

### 1.1 四个必须做实的模块

| 模块 | 能力 | 关键约束 |
| --- | --- | --- |
| 帖子管理 | 查看、搜索、筛选、编辑正文与置顶、审核（通过 / 驳回 / 打回待审）、删除、批量操作 | 状态机固定四态，审核必须留痕（审核人 / 时间 / 意见） |
| 用户管理 | 列表、注册信息、详情、改等级 / 徽章、禁用 / 启用、删除 | 禁用要**当场**踢掉该用户的站点会话；删除要显示级联影响 |
| 奖励发放 | 向指定用户发积分 / 会员天数 / 自定义奖励，记录原因，撤回，导出 | 发放与积分变动同一事务；撤回只能撤 active，重复撤回报 409 |
| 权限管理 | 角色 CRUD、18 项权限勾选、管理员账号 CRUD / 重置密码 / 停用 | 权限**每次请求回表**，改完下一次请求即生效 |

### 1.2 两条贯穿全局的硬要求

1. **登录验证界面**：独立登录页，带账号密码、失败次数提示、锁定倒计时、错误不泄露账号是否存在。
2. **操作日志**：所有写操作 + 登录成功 / 失败都落 `admin_logs`，30 个动作名受契约约束，可按管理员 / 动作 / 对象 / 时间筛选与导出。

### 1.3 明确不做的

- 不接管站点前台的身份（不写 `users` 表、不签发站点 cookie）。
- 不做内容编辑器（富文本 / 图片上传走站点既有能力），后台只处理纯文本正文与状态。
- 不做多租户、不做 OAuth / 扫码登录、不做审批流引擎 —— 单人运维规模下都是负债。

## 2. 总体架构

```
浏览器  /admin/  (零依赖 ES Module SPA)
   │  fetch('/api/admin/*', credentials:'same-origin')   ← HttpOnly cookie
   ▼
dev-server.mjs (8777)  ──静态托管仓库根 + 反代 /api → 127.0.0.1:3000──▶  Fastify (3000)
                                                                          │
                                       ┌──────────────────────────────────┤
                                       │ admin-guard.js  requireAdmin      │
                                       │                 requirePermission │
                                       ▼                                  ▼
                              admin_* 表 (SQLite)                  users / posts / comments
```

**为什么前端放在 `admin/` 而不是主站 hash 路由里**：

- 主站 `index.html` 是零构建的社交界面，把后台塞进去会让两套布局、两套鉴权、两套路由互相污染。
- `admin/` 是同源目录，Cookie 天然生效，不需要 CORS，也不需要把 token 放进 localStorage（XSS 拿不到 HttpOnly）。
- 后端只挂 `/api/admin/*` 前缀，与站点 API 完全隔离；`requireAdmin` 校验 JWT 里的 `scope:'admin'`，站点用户 token 打进来一律 401。

**进程与端口**

| 端口 | 作用 | 说明 |
| --- | --- | --- |
| 3000 | Fastify 后端 | 站点 API + 后台 API 同一个进程 |
| 8777 | dev-server | 静态站点 + `/api` 反代，浏览器只看到一个源 |
| 3102 | 联调专用实例 | `DB_PATH=data/admin-lead.db PORT=3102`，不碰生产库 |

## 3. 数据模型

新建 5 张表（`server/src/schema-admin.sql`），另给两张既有表补列。**全部幂等**：建表失败只 `warn`，不阻断站点启动。

### 3.1 admin_roles（角色）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | |
| key | TEXT UNIQUE | `owner` / `admin` / `editor` / `staff` / `role_<id>` |
| name / description | TEXT | 展示用 |
| permissions | TEXT(JSON) | 权限 key 数组，元素必须在权限目录内 |
| builtin | INTEGER | 1 = 内置，不可删除；owner 的权限不可改 |
| created_at / updated_at | INTEGER | Unix 秒 |

> 权限存 JSON 而不是拆关联表：权限总量固定 18 个、角色个位数，读一次 `JSON.parse` 比三表 join 便宜；
> 真正的约束在写入侧 —— `normalizePermissions()` 会剔除目录外的 key 并去重。

### 3.2 admin_accounts（后台账号）

| 字段 | 说明 |
| --- | --- |
| account | `COLLATE NOCASE UNIQUE`，大小写不敏感，避免 root / Root 变成两个号 |
| name | 显示名 |
| password_hash | bcryptjs，10 轮 |
| role_id | → admin_roles(id)，`ON DELETE RESTRICT`（有成员的角色删不掉） |
| status | active / disabled |
| failed_count / locked_until | 连续失败计数与解锁时间，**直接放账号行**（后台账号个位数，不值得单独建表） |
| last_login_at / last_login_ip | 登录审计辅助 |

### 3.3 admin_sessions（会话）

- `id` 是 48 位十六进制字符串，不是自增整数：sid 要进 JWT，整数可枚举。
- `token_hash = sha256(完整 token)`：库泄露也换不出可用 cookie（与前台 sessions 同口径）。
- `admin_id` 上 `ON DELETE CASCADE`：账号删除后会话必须一起消失。

### 3.4 rewards（奖励账本）

| 字段 | 说明 |
| --- | --- |
| user_id | → users(id) `ON DELETE CASCADE` |
| type | `points`（积分）/ `days`（会员天数）/ `custom`（纯记账，不改表） |
| amount | points/days 为数量，custom 必须为 0 |
| reason | **必填**，发放原因 |
| note | 可选备注 |
| status | active / revoked |
| granted_by / granted_at | 发放人 id 与时间 —— **不建外键**，管理员离职删号后账目仍要可查 |
| revoked_by / revoked_at / revoked_reason | 撤回信息 |

### 3.5 admin_logs（操作日志）

| 字段 | 说明 |
| --- | --- |
| admin_id / admin_name / role_key | 冗余落库，日志要比账号活得久；"当时的角色"本身就是审计信息 |
| action | 30 个动作名之一（小写点分），含 2FA 与登录挑战事件 |
| target_type / target_id | 对象类型与 id |
| summary | 一句话摘要（列表页直接显示） |
| detail | JSON `{before, after, note}`，只在详情抽屉里读，不进列表 |
| result | ok / fail |
| ip / created_at | |

> 失败登录也写这张表（`admin_id=0`，`admin_name` 记被尝试的账号名），否则撞库在后台完全不可见。

### 3.6 既有表补列

| 表 | 新列 | 用途 |
| --- | --- | --- |
| posts | status（默认 `published`）、review_note、reviewed_by、reviewed_at | 四态：published / pending / rejected / hidden |
| users | status（默认 `active`）、disabled_reason、disabled_at、points | 禁用与积分余额 |

补列走 `PRAGMA table_info` + `ALTER TABLE`，已存在就跳过。

## 4. 权限模型（RBAC）

### 4.1 权限目录（18 项，6 组）

| 组 | 权限 | 说明 |
| --- | --- | --- |
| 工作台 | `dashboard.view` | 概览指标与待办 |
| 内容 | `post.view` `post.edit` `post.review` `post.delete` | 查看 / 改正文置顶 / 审核 / 删除 |
| 用户 | `user.view` `user.edit` `user.status` `user.delete` | 查看 / 改等级徽章 / 禁用启用 / 删除 |
| 运营 | `reward.view` `reward.grant` `reward.revoke` | 查看 / 发放 / 撤回 |
| 权限 | `role.view` `role.manage` `admin.view` `admin.manage` | 角色与管理员 |
| 系统 | `log.viewAll` `log.export` | 全部日志 / 导出 |

### 4.2 四个内置角色

| 角色 | 权限 | 定位 |
| --- | --- | --- |
| owner | 全部 18 项 | 站长，唯一能改角色与管理员 |
| admin | 除 `role.manage` `admin.manage` 外 16 项 | 日常总管，能删帖删用户但不能动权限体系 |
| editor | `dashboard.view` `post.view` `post.edit` `post.review` `user.view` `reward.view` | 内容编辑：能审不能删，能看用户不能改 |
| staff | `dashboard.view` `post.view` `user.view` `reward.view` | 值班：全只读 |

### 4.3 三条生效规则

1. **权限不进 JWT**：JWT 只带 `{aid, sid, scope:'admin'}`，每次请求按 `role_id` 回表读 `permissions`。
   改完角色权限，**同一个 cookie 的下一次请求就生效**（8 小时过期不再是等待窗口）。
2. **数据范围也是权限**：没有 `log.viewAll` 时日志接口强制 `scope=self`，只能看自己的操作 —— 这比"前端不显示"可靠。
3. **自保护**：不能改自己的角色、不能删自己、不能改 owner 角色的权限、不能删内置角色、不能删还有成员的角色、不能删最后一个 active owner。

### 4.4 越权的返回形状

`403 { ok:false, error:{ code:'FORBIDDEN', message:'没有这个操作权限', need:'post.delete' } }`
`need` 直接告诉前端缺哪一项，页面据此隐藏按钮；即使前端被绕过，后端仍然拦。

## 5. 登录与会话安全

| 项 | 做法 | 理由 |
| --- | --- | --- |
| 凭据 | `account` + `password`（bcryptjs 10 轮） | 与站点同栈，无新依赖 |
| 会话 | JWT（`@fastify/jwt`，与站点共用 secret）payload `{aid,sid,scope:'admin',amr}`，另存 `admin_sessions` 行 | 可服务端吊销；`scope` 防止站点 token 串门；`amr` 记录本次登录是否过 TOTP |
| Cookie | `whale_admin_token`，HttpOnly、SameSite=Lax、Path=/、Max-Age=28800（8 小时） | 与站点 `jingyu_token` 分开，互不顶号 |
| 暴力破解 | 连续失败 5 次锁 15 分钟；第 5 次当场返回 `423 {retryAfter:900}`；锁定期内正确密码也 423 | 锁定写在账号行，重启不丢 |
| 限流 | 登录 30 次 / 5 分钟 / IP | 够人工重试，挡脚本撞库 |
| 枚举 | 账号不存在时也跑一次 bcrypt（`DUMMY_HASH`），文案统一"账号或密码不对" | 时序与文案都不泄露账号是否存在 |
| 两步验证 | TOTP（RFC 6238，SHA-1 / 6 位 / 30 秒 / ±1 步）；`owner`、`admin` 角色**强制**，其余角色可自愿开启 | 后台权限最重的两个角色只靠密码风险太高 |
| 挑战令牌 | 密码通过后先发 10 分钟短命 JWT（`scope:'admin_2fa'`，绑定 UA 哈希），**不下发登录 cookie** | 密码正确但第二因素未过时，拿不到任何后台权限 |
| 恢复码 | 启用时一次性返回 8 个 `XXXX-XXXX`，库中只存 sha256；每个只能用一次 | 换手机 / 丢验证器时的唯一自助出口 |
| 防重放 | `totp_last_step` 只接受严格递增的步数，同窗口重复提交 `409 CODE_REPLAY` | 防同一 6 位码被截获后重放 |
| 改密 | 校验旧密码，成功后**删除其它会话**，当前会话保留 | 密码泄露时能一脚踢掉所有旧设备 |
| 登出 | 删会话行 + 清 cookie + 写 `auth.logout` | 服务端立即失效，不等 JWT 过期 |

## 6. 功能说明

### 6.1 登录页

- 左侧品牌区（鲸域标识、版本、一句说明），右侧表单；窄屏自动单列。
- 账号 / 密码 / 显示密码 / 记住账号（只记账号名，不记密码）。
- 第二步：`owner` / `admin` 首次登录进入「绑定两步验证」——扫码或手抄密钥、输入 6 位码、保存 8 个恢复码；已绑定的账号进入「两步验证」——输入 6 位码，或改用恢复码。
- 失败：`账号或密码不对`（不区分哪个错）；验证码错误与密码错误共用 5 次锁定；锁定：倒计时 + "15 分钟后再试"；停用：`账号已停用，请联系 owner`。
- 绑定成功后恢复码页强制勾选「我已保存」才能进控制台；恢复码只显示这一次。
- 已登录访问 `#/login` 自动跳 `#/dashboard`；未登录访问任何页面跳登录并记住来源路由。

### 6.2 工作台（`#/dashboard`）

- 4 张主 KPI 卡：帖子总数（今日 +n）、待审核（队列是否清空）、用户总数（今日 +n、已禁用 n）、今日奖励（累计发放积分）。接口 `/stats/overview` 实际返回 9 项指标（另含评论总数、奖励笔数、今日发帖、在线管理员等），前端按「先看四件事」取舍只渲染 4 张主卡，其余作为后续扩展位，避免首屏数字过密。
- 7 / 14 / 30 天趋势图，三条序列：新帖子 / 新用户 / 奖励发放；纯 SVG 折线 + 面积，无图表库，切换天数即时重绘。
- 待办与动态：待审核空态卡片（队列清空时给出「去帖子管理主动翻一遍」的出口）、最近操作 Top 5（按权限显示范围）、近 7 天动作分布条、最近奖励。
- 每个数字与卡片可点，跳到对应列表并带上筛选条件。

### 6.3 帖子管理（`#/posts`）

- 顶部状态页签：全部 / 已发布 / 待审核 / 已驳回 / 已隐藏，各带计数。
- 搜索：标题 + 正文 + 作者（LIKE 转义，`%_` 不会变成通配符）；排序：最新 / 最早 / 评论最多。
- 列表列：标题（含置顶标记）、作者、状态 pill、评论数、浏览、发布时间、操作。
- 行操作：查看详情（右侧抽屉，含评论列表）、编辑（正文 / 置顶）、审核（通过 / 驳回 / 打回待审，可填意见）、删除（二次确认）。
- 批量：勾选后批量通过 / 批量驳回 / 批量删除，返回 `{affected:n}`。
- 空态、加载骨架、错误重试三态齐全。

### 6.4 用户管理（`#/users`）

- 列表：头像、昵称、邮箱（默认打码 `te***@example.com`）、等级徽章、状态、注册时间、帖子数、积分。
- 搜索：邮箱 / 昵称 / 手机号后四位；筛选：正常 / 已禁用 / 管理员（level≥15）。
- 详情抽屉：完整邮箱与手机号（仅 `user.view` 可见）、注册信息、发帖数 / 评论数 / 获赞、最近帖子、奖励历史。
- 编辑：等级（0–20）、徽章；禁用：必须填原因，禁用后该用户的站点会话**立即失效**，再登录返回 `ACCOUNT_DISABLED`；启用即恢复。
- 删除：先展示级联影响（帖子 / 评论 / 会话数量），确认后删除。

### 6.5 奖励发放（`#/rewards`）

- 发放表单：选用户（搜索选择器）、类型（积分 / 会员 / 头像框 / 自定义）、数量、原因（必填，≥2 字）、备注。
- 选中用户后显示会员面板：当前档位与到期日（未开通显示"未开通"）、当前头像框；数据来自 `GET /rewards/options?userId=`。
- 积分类型在同一事务内 `users.points += amount`；会员类型写 `member_subs` 并在 `member_events` 记一条手工流水；头像框类型写 `users.frame` 并记录 `prev_frame` 以便撤回还原；失败整体回滚。
- 历史列表：时间、用户、类型、数量、原因、发放人、状态；可按类型 / 状态 / 用户 / 时间筛选。
- 撤回：只能撤 active，必须填撤回原因；积分扣回、会员按天回退、头像框还原上一款；重复撤回返回 `409`。
- 汇总条：累计发放笔数、本月发放、撤回笔数。
- 导出 CSV（BOM + CRLF，Excel 直接打开不乱码）。

### 6.6 角色与管理员（`#/roles`）

- 左栏角色列表（内置角色带"内置"标记），右栏权限矩阵：6 组 × 18 项开关，全选 / 反选 / 按组选。
- 新建角色：名称、标识（自动生成 `role_<id>`）、描述、权限勾选；保存后立刻可用于建号。
- 管理员列表：账号、姓名、角色、两步验证状态、状态、最后登录时间 / IP、操作（改角色 / 重置密码 / 重置两步验证 / 停用 / 删除）。
- 两步验证列区分「已绑定 / 未绑定」；对已绑定且非本人的账号提供「重置两步验证」，清空 secret 与恢复码并撤销该账号全部会话，用户下次登录重新扫码。
- 受保护操作在界面上直接禁用并给出原因（不能删自己 / 不能改自己角色 / 不能重置自己的两步验证 / 内置角色不可删）。

### 6.7 操作日志（`#/logs`）

- 筛选：管理员、动作（30 项下拉，中文名）、对象类型、结果、时间范围、关键词。
- 列表：时间、管理员（角色）、动作、对象、摘要、结果、IP。
- 详情抽屉：`detail` 的 before / after 对比（改前 / 改后字段级高亮）。
- 范围：有 `log.viewAll` 看全部，否则只看自己（后端强制，前端在页头标注"仅显示我的操作"）。
- 导出 CSV，受 `log.export` 控制。

## 7. API 一览

完整字段见 `docs/admin-api.md`。统一约定：前缀 `/api/admin`、成功 `{ok:true,data}`、失败 `{ok:false,error:{code,message}}`、camelCase、Unix 秒、分页 `page/pageSize`（≤100）。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/login` | — | 密码登录；需要 2FA 时返回挑战而不是 cookie |
| POST | `/auth/2fa/verify` | 挑战令牌 | 输 6 位码或恢复码，完成登录 |
| POST | `/auth/2fa/enable` | 挑战令牌 | 首次绑定，返回 8 个恢复码 |
| GET | `/auth/2fa/status` | 登录 | 当前账号 2FA 状态与剩余恢复码 |
| POST | `/auth/2fa/disable` | 登录（非 owner/admin） | 密码 + 验证码双确认关闭 |

## 8. 前端实现

- **零依赖、零构建**：原生 ES Module + 手写 DOM，`admin/index.html` 只引 3 个 CSS 与 1 个入口 `js/boot.js`。
- **模块划分**：`core.js`（请求 / 状态 / 组件 / 表单 / 抽屉 / 弹窗 / 提示）、`shell.js`（侧栏 / 顶栏 / 路由外壳）、`page-*.js`（六个页面）、`boot.js`（会话恢复与首屏）。
- **路由**：hash 路由 `#/dashboard`…，支持刷新直达与前进后退；未登录统一跳 `#/login?next=…`。
- **视觉**：深海军蓝侧栏（`#0a1b2b → #0d2436`）、浅灰蓝内容区（`#f2f6fb`）、主色 `#1775c8`；状态 pill 固定语义色（已发布绿 / 待审琥珀 / 驳回红 / 隐藏灰）。
- **交互**：抽屉 240ms 滑入、表格行 52px、骨架屏、Toast、确认弹窗、权限不足时按钮置灰并显示原因。
- **响应式**：≥1200 三栏、768–1199 侧栏图标态、<768 抽屉式侧栏 + 卡片化表格。
- **主题**：深浅两套，`localStorage['whale-admin-theme']` 记忆；`admin/index.html` 在样式表之前跑一段同步守卫，先定 `data-theme` 再绘制，夜间刷新不会闪一帧白底。该守卫是内联脚本，线上 CSP 必须登记它的 sha256（见 9.3）。

## 9. 部署与运维

### 9.1 首次上线

```bash
cd server
npm install
ADMIN_SEED_PASSWORD='换成一个强密码' node scripts/seed-admin.js     # 只建 root
cd ..
node dev-server.mjs                                                 # 开发：8777 静态 + /api 反代
# 生产：nginx 托管静态 + 反代 /api 到 3000
```

- `seed-admin.js` 幂等：角色由 `initAdminSchema` 种；已有账号且未给密码时只补角色 / 姓名，不动密码。
- 忘记密码：`ADMIN_SEED_PASSWORD='新密码' node scripts/seed-admin.js` —— 只要给了密码，脚本就会给已有账号重设密码并清零失败计数（不动角色与姓名）。
- 生产建议：`JWT_SECRET` 必须显式设置（缺省会落到 `dev-only-insecure-secret-change-me`）；后台仅内网或加 IP 白名单；nginx 对 `/admin/` 加 `Cache-Control: no-store`。
- 启用 2FA 还必须设置 `ADMIN_TOTP_KEY`（`openssl rand -hex 32`），**与 `JWT_SECRET` 分开**。它负责加密库里的 TOTP secret：缺失或更换会让已绑定账号无法解密，只能逐个重置 2FA；备份数据库时要把它一起离线保存。
- 忘记验证器：优先让另一个管理员在「权限管理 → 管理员账号」点「重置两步验证」；只剩自己时在服务器跑 `node scripts/reset-admin-2fa.js <账号>`，然后重新登录扫码。

### 9.2 备份

- 后台数据全在同一个 SQLite 文件里，备份就是复制 `server/data/jingyu.db`（WAL 模式下用 `sqlite3 .backup` 或停写复制）。
- 奖励与日志是账本，恢复时不要只挑表恢复。

### 9.3 打包

`deploy/build.mjs` 会给主站 `index.html` 引用的 css/js 加内容哈希；后台是独立入口，按目录整体复制即可（`admin/` → `dist/admin/`），并跳过以 `_` 开头的调试脚本。

**CSP 对账（必做）**：后台入口有一段内联的主题首绘守卫，线上 `/etc/nginx/snippets/security-headers.conf` 的 `script-src` 用的是 sha256 白名单。构建会把 4 条内联脚本哈希写进 `dist/csp-hashes.json`，其中第 4 条是 `admin/index.html`：

```bash
node -e "const j=require('./dist/csp-hashes.json');for(const x of j.inline)console.log(x.where,x.hash)"
# admin/index.html sha256-Bp2TECQmDqRVcZ2ecpZZtvQm3oG2XP5jVixN0aKsgC8=
```

部署时把该条补进 `script-src`，否则线上后台的夜间模式会被 CSP 拦掉（表现为刷新后总是白天），而本地一切正常。改了守卫内容就要重新登记哈希。

## 11. 已知边界

1. 自定义角色的 `key` 用 `role_<id>`，id 会因启动时 `INSERT OR IGNORE` 消耗自增而跳号（如 `role_13`），不影响功能。
2. "最后一个 active owner"保护存在 409 分支，但正常路径下自删会先被 403 拦住，脚本未单独构造该场景。
3. 日志 `detail` 目前记录 before/after 快照，不做字段级 diff 存储（前端渲染时对比）。
4. IP 白名单未做在应用层，交给 nginx / Cloudflare；Cloudflare 回源白名单目前仍是有意延后状态（见 `docs/cloudflare-接入记录-20261024.md`）。
5. 恢复码重新生成已有接口 `POST /auth/2fa/recovery-codes`，界面暂未挂入口，需要时用接口或后续补按钮。
6. 后台入口 `admin/index.html` 有一段内联主题守卫，线上 CSP 需要单独登记它的 sha256（见 9.3）；漏登记的表现是「夜间模式刷新后回白天」，不会报错。

### 14.1 「保存新密码」点击无反应（2026-10-24 修复，已上生产）

**现象**：账号菜单 →「修改密码」，填完三项点「保存新密码」毫无反应：没有 spinner、没有错误、弹窗不关、网络面板也没有请求。

**根因**：`admin/js/shell.js` 的 `openPassword()` 里，保存按钮通过 `ctx.body.querySelector('#pw-ok')` 查找，**但按钮写在 `footer`**。`core.js` 的 `openModal()` 里 `ctx.body` 只指向 `.modal-bd`，footer 是兄弟节点 `.modal-ft`，所以查询结果恒为 `null`；紧接着的 `okEl.addEventListener(...)` 抛 `TypeError`，被点击事件吞掉 —— 弹窗照常渲染，按钮从未绑定监听，于是「完全没反应」而不是「点了报错」。

**修法**：
1. 改成 `ctx.footer.querySelector('#pw-ok')`，与 `page-roles.js`（`ctx.footer.querySelector('[data-act="create"]')`）和 `confirmDialog` 的既有写法一致；
2. 校验补到与后端 `validPassword()`（`admin-guard.js:128`：8~64 位且同时含字母和数字）一致，不再只在 length<8 时拦截；
3. 提示文案由「至少 8 位，建议混合字母与数字」改为「8～64 位，需同时包含字母和数字」；
4. 三个输入框支持回车提交；`busy` 标志防止连点重复提交；
5. `page-roles.js` 的「新建管理员」「重置密码」两个弹窗同步对齐同一条密码规则（后端本来就会拒，前端先拦住，省一次报错）。

**验收**：
- 本地 CDP 自动化 5 条路径：成功改密（弹窗关闭 + toast「密码已更新」）、纯字母口令（行内「新密码需同时包含字母和数字」）、两次不一致、原密码错（「原密码不对」）、回车提交成功；控制台零异常。
- 生产实测：登录 → 打开弹窗 → 故意填错原密码 → `POST /api/admin/auth/password` 真实发出、行内显示「原密码不对」，字体与提示为新版；截图 `screenshots/admin-pw-dialog-prod.png`。
- 回归：`qa/admin-e2e.mjs` 94 项全过。

## 15. 会员档位与头像框（2026-10-24 新增）

### 15.1 为什么加

奖励页原来只有「积分 / 会员天数 / 自定义」三类。会员天数只知道天数，不知道天数是哪个档位；头像框属于纯装饰权益，只能改库。运营想要的是：**发会员时直接选档位**，**发装饰时直接挑框**，并且发完当场看见结果。

### 15.2 数据契约

| 位置 | 字段 | 说明 |
|---|---|---|
| `member_plans` | tier / price_cents / duration_days | 档位与价格来自站点既有的会员套餐表，后台不另建一份 |
| `member_subs` | tier / expires_at / updated_at | 后台发会员只写这张表（`user_id` 唯一） |
| `member_events` | kind='manual' / tier / days / actor / note | 手工发放与撤回都留一条资金侧流水，和订单流水同一张表 |
| `users` | frame | `auto` = 跟随会员档位；`maw-1..4` = 指定头像框；`none` = 不戴 |
| `rewards` | tier / frame / prev_frame | 奖品快照：发的是哪个档位、哪个框、换之前是什么框 |

档位固定四档：`diamond`（钻石 ¥19 起）、`master`（大师 ¥58 起）、`grandmaster`（宗师 ¥138 起）、`hunt`（猎杀 ¥388 起）。头像框六选一：跟随档位 / 冷钢 Lv1 / 紫铜 Lv2 / 赤金 Lv3 / 血红 Lv4 / 不戴。

### 15.3 交互

1. 类型从三档变四档：**积分 / 会员 / 头像框 / 自定义**。切到「会员」出现 2×2 档位卡（色点 + 名称 + 起价 + 默认天数），切到「头像框」出现 3×2 框卡（框名 + 等级）。
2. 选用户后，表单里多一条会员面板：`档位 · 到期日` + `头像框：xxx`；换用户会重新拉 `/rewards/options?userId=`。
3. 预览句随类型变化：会员 →「将向 X 发放 30 天「猎杀」会员（当前不是会员）」；头像框 →「将把 X 的头像框换成 屠场 · 赤金（当前：跟随会员档位）」。
4. 提交成功后：toast + 表单下方结果条 + 会员面板同步刷新，并把结果条滚进视野；原因与备注清空，用户与档位保留，方便连发。
5. 历史行：会员行在金额位显示「+30 天 · 猎杀」，另起一行 meta 标注档位与到期；头像框行显示「头像框 · 赤金 Lv3」，不再重复 meta。

### 15.4 服务端语义

- `POST /api/admin/rewards`：
  - `type=days` 必须带 `tier`，`amount` 1~3650；同档位累加到期日，跨档位按剩余天数折算，降档拒绝（与站点升级逻辑一致）。
  - `type=frame` 必须带 `frame`，`amount` 必须 0；写入前把原值记到 `rewards.prev_frame`。
  - 非法档位 400「档位只支持 diamond / master / grandmaster / hunt」，非法头像框 400「头像框不在可选范围里」。
  - 写日志：会员与积分走 `reward.grant`，头像框单独记 `reward.frame`「更换头像框」，方便审计筛出装饰性变更。
- `POST /rewards/:id/revoke`：会员按天回退，退回 0 天时档位置 `free` 且 `expires_at` 一并清零（否则面板会显示「已到期」而档位是旅人，像脏数据）；头像框还原 `prev_frame`；两种情况都写一条负数 `member_events` 或还原记录。
- `GET /rewards/options?userId=` 一次返回 `{tiers, frames, presets, limits, user}`；`user` 是会员面板（`tier/tierName/tierAccent/tierActive/expiresAt/daysLeft/frame/frameLabel/frameFollow`）。前端只在进入页面和换用户时各拉一次。
