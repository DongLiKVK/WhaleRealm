# VPN（自建代理）部署记录 · 2026-10-25

> 目标：在境外服务器 `158.247.215.153` 上自建代理，本机（Windows）可一键翻墙。
> 约束：该机同时是 **whalerealm.top 生产机**，nginx 占用 80/443(TCP)，全程未改动生产站点。

## 一、服务器与线路

| 项目 | 值 |
| --- | --- |
| 主机 | `158.247.215.153`（别名 jingyu-deploy / Vultr 韩国） |
| 系统 | Ubuntu 22.04.5 LTS，内核 5.15.0-198-generic，1 vCPU / 951MB RAM |
| 既有服务 | nginx(80/443 TCP)、Node 站点 127.0.0.1:3000、sshd(22)、fail2ban、UFW、BBR+fq |
| 新增线路 A | **VLESS + XTLS-Vision + REALITY** → `TCP 8443`（主力） |
| 新增线路 B | **Hysteria2** → `UDP 443`（备用，抗丢包） |

为什么不用 443/TCP 跑代理：443/TCP 已被生产 nginx 占用且走 Cloudflare；UDP 443 与 TCP 443 是不同协议栈，互不冲突，所以 Hysteria2 可以安全地吃掉 UDP 443。

## 二、部署步骤（服务器端）

### 1. 放行端口

```bash
ufw allow 8443/tcp comment 'xray-vless-reality'
ufw allow 443/udp  comment 'hysteria2'
ufw status numbered
```

### 2. Xray（REALITY）

```bash
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install
xray x25519                      # 生成 REALITY 密钥对，私钥填服务端、公钥给客户端
xray x25519 -i <私钥>            # 反查公钥（Password/PublicKey）
```

`/usr/local/etc/xray/config.json` 关键片段（旧配置已备份为 `config.json.bak.*`）：

```json
{
  "inbounds": [
    {
      "listen": "0.0.0.0",
      "port": 8443,
      "protocol": "vless",
      "settings": {
        "clients": [
          { "id": "1d2c552a-e676-4631-82f5-dfb5dced88e3", "flow": "xtls-rprx-vision" }
        ],
        "decryption": "none"
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "show": false,
          "dest": "www.nvidia.com:443",
          "xver": 0,
          "serverNames": ["www.nvidia.com"],
          "privateKey": "cKyi-WXIDvlaedPc3rzAWAB-7Q4i1OjO8J0iIOgK-ko",
          "shortIds": ["89e4a36e4f195583"]
        }
      },
      "sniffing": { "enabled": true, "destOverride": ["http", "tls", "quic"] }
    }
  ],
  "outbounds": [
    { "protocol": "freedom", "tag": "direct", "settings": { "domainStrategy": "UseIP" } },
    { "protocol": "blackhole", "tag": "block" }
  ],
  "routing": {
    "rules": [
      { "type": "field", "ip": ["geoip:private"], "outboundTag": "block" }
    ]
  }
}
```

```bash
xray -test -c /usr/local/etc/xray/config.json   # 必须 0 报错；先看有无 REALITY 目标站告警
systemctl enable --now xray && systemctl status xray --no-pager
```

> 目标站选择踩坑：`www.microsoft.com` / `www.apple.com` / `icloud` / `swdist` 会被 xray 警告 *“Choosing X as the target will increase the likelihood of your server IP being blocked by the GFW”*；改用 `www.nvidia.com` 无告警。

### 3. Hysteria2

```bash
bash <(curl -fsSL https://get.hy2.sh/)
mkdir -p /etc/hysteria
openssl ecparam -genkey -name prime256v1 -out /etc/hysteria/key.pem
openssl req -new -x509 -days 3650 -key /etc/hysteria/key.pem -out /etc/hysteria/cert.pem \
  -subj "/CN=www.nvidia.com"
```

`/etc/hysteria/config.yaml`：

```yaml
listen: :443

tls:
  cert: /etc/hysteria/cert.pem
  key: /etc/hysteria/key.pem

auth:
  type: password
  password: 7f3c9b21d84ea65c0f2b91a7

masquerade:
  type: proxy
  proxy:
    url: https://www.nvidia.com/
    rewriteHost: true
```

`/etc/systemd/system/hysteria-server.service` 两个关键点（否则 443 绑不上）：

```ini
User=hysteria
AmbientCapabilities=CAP_NET_BIND_SERVICE
```

```bash
chown -R hysteria:hysteria /etc/hysteria
systemctl daemon-reload && systemctl enable --now hysteria-server
```

## 六、换端口预案（8443 被干扰时）

1. 改服务端 `/usr/local/etc/xray/config.json` 的 `port`，`systemctl restart xray`；
2. `ufw allow <新端口>/tcp` 并 `ufw delete allow 8443/tcp`；
3. 客户端改端口即可（UUID / 公钥 / ShortId / SNI 都不用变）；
4. 或直接切 Hysteria2 线路（UDP 443），两条同时挂掉的概率很低。

## 七、回滚（完全撤掉代理，恢复部署前状态）

```bash
systemctl disable --now xray hysteria-server
ufw delete allow 8443/tcp
ufw delete allow 443/udp
rm -rf /usr/local/etc/xray /etc/hysteria
```

生产站点 nginx / jingyu.service 全程未触碰，无需回滚。

## 八、事件与教训

- **fail2ban 误封本机**：首次探测时认证失败次数过多，`111.31.187.43` 被 sshd jail 封 1 天。解决：经腾讯云跳板 `43.142.153.74` 进服务器执行 `fail2ban-client set sshd unbanip 111.31.187.43`。之后所有服务器操作统一走 `C:\Users\Administrator\.ssh\config_whale` 的 ProxyJump 别名 `whale`，并强制 `ControlMaster no`（否则 mux 多路复用会 reset）。
- **REALITY 非 443 端口有告警**：xray 会提示非 443 监听更容易被针对，但 8443 实测稳定；必要时按第六节换端口。
- **sing-box 连 REALITY 失败**：sing-box 1.14.4 用同一组参数报 `reality verification failed`，Xray 客户端正常。结论：Windows 端 REALITY 一律用 xray 内核，sing-box 只跑 hy2。
- **bat 编码**：含中文的 `.bat` 必须 CRLF + GBK，`.ps1` 必须 UTF-8 **带 BOM**，否则中文乱码或整行解析失败。
