# 登录与第三方授权（邮箱 + GitHub）

2026-10 起鲸域只保留两种登录：**邮箱 + 密码**，和 **GitHub 一键授权**。手机号认证闸门已从前端移除（服务端 `/api/auth/phone/*` 与 `server/src/sms/*` 仍保留，未接短信商，暂时没人调用）。

## 一、线上实际行为

| 场景 | 落地 |
| --- | --- |
| 邮箱注册 / 登录 | `POST /api/auth/register`、`/login`，成功后直接进 `#/feed`，不再跳 `#/verify` |
| 点 GitHub 按钮 | `location.assign('/api/auth/oauth/github/start?redirect=…')` → 302 到 github.com 授权页 |
| 授权成功回调 | 服务端建会话 → 302 回 `/#/login?oauth=ok&provider=github` → 前端 `settleOauthReturn()` 认领身份 → 清掉 query 并进 `#/feed`，右下角弹「欢迎回来」 |
| 用户点了取消 | 回调 `/#/login?oauth=error&code=OAUTH_DENIED` → 登录表单上方红条：「你在授权页点了取消，随时可以再来」 |
| 没配 key | `/api/auth/oauth/providers` 里 github `enabled:false`，登录页的「其他方式登录」整块不渲染（不是置灰按钮） |

代码位置：`js/app.js` 的 `settleOauthReturn()`（在 `applyHash()` 上方）、`js/auth.js` 的 `oauthStart/oauthComplete`、`server/src/routes/oauth.js`。

## 二、配置 GitHub OAuth App（唯一需要人工做的一步）

1. 打开 <https://github.com/settings/developers> → **New OAuth App**
2. 填三个值：
   - Application name：`鲸域 WhaleRealm`
   - Homepage URL：`https://whalerealm.top`
   - Authorization callback URL：`https://whalerealm.top/api/auth/oauth/github/callback` ← **必须一字不差**
3. 创建后复制 **Client ID**，再点 **Generate a new client secret** 复制 secret（只显示一次）

## 三、写入服务器

```bash
bash deploy/overseas/oauth-github.sh <CLIENT_ID> <CLIENT_SECRET>
```

脚本做四件事：删掉 `.env` 里旧的 `OAUTH_GITHUB_*` 行 → 追加新值 → `chown jingyu` + `chmod 600` → `systemctl restart jingyu`，最后打印 `/api/auth/oauth/providers`。看到 `github … "enabled":true` 就通了，刷新登录页即出现 GitHub 按钮。

回滚：`ssh root@158.247.215.153 "sed -i '/^OAUTH_GITHUB_/d' /var/www/jingyu/server/.env && systemctl restart jingyu"`

## 四、验证清单

```bash
curl -sS https://whalerealm.top/api/auth/oauth/providers        # configured 应为 1，github enabled:true
curl -sS -o /dev/null -w '%{http_code}\n' https://whalerealm.top/api/auth/oauth/github/start   # 302
```

浏览器里：点 GitHub → 授权 → 应直接落在首页且导航显示 GitHub 昵称；退出后再登一次应复用同一个账号（占位邮箱 `github_<openid>@oauth`，故意不合法，避免被密码通道抢注）。

## 五、注意

- 用 `curl -d` 传含中文的 JSON 会得到 `FST_ERR_CTP_INVALID_CONTENT_LENGTH`，改用 `--data-binary @file`。
- 已登录状态下再点第三方授权，服务端直接 409 `ALREADY_AUTHED`（换号后门）。
- 第三方账号没公开邮箱时，邮箱是空的；设置页「登录方式」显示「github 账号（未设密码）」。

## 头像继承、白板账号与公开资料（2026-10-24）

三处改动一起才让「GitHub 登录」看起来像一个正常账号：

1. **头像继承**：`server/src/routes/oauth.js` 的 `insertUser` 现在会把 `avatar` 一起写进 `users` 表；
   老账号在回调里补一次 `UPDATE users SET avatar = ?`（仅在 `users.avatar = ''` 时，绝不覆盖用户自己换过的图）。
   CSP 里 `img-src` 放行了 `https://avatars.githubusercontent.com` —— 不加这一条，GitHub 头像会被浏览器静默拦掉。
2. **白板账号**：服务端账号的 uid 是 `s + id`（演示账号仍是 `u1..u8`），两套命名空间不再撞车。
   新账号从 `blankUserRow()` 起步：0 粉丝 / 0 关注 / 0 访客，资料卡只显示昵称与等级。
3. **落地页**：`#/welcome` 会在「已登录但签名和城市都空」时接管一次，填完（或点「先逛逛」）才放行到 `#/feed`；
   跳过状态记在 `localStorage['dsh-profile-skip:<uid>']`，不会每次登录都拦。

公开资料接口：`GET /api/users/:uid`（`server/src/routes/users.js`），只返回 `publicUser()` 的字段，
用于让别人的空间页显示正确的名字与头像；`#/space/<uid>` 在拿不到资料前显示「正在打开这个空间…」，
不再退回 `u1` 的演示数据。

回滚：`git checkout -- js/app.js js/auth.js js/api.js js/membership.js server/src/routes/oauth.js server/src/index.js`
并删掉 `server/src/routes/users.js`、`css/onboarding.css`，然后重新 `backend` + `frontend` 部署。
