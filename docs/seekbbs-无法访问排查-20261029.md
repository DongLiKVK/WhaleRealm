# seekbbs.cn 打不开：原因与解决办法

> 一句话：**域名没有 A 记录，浏览器拿不到 IP**。服务器本身已经能正常提供服务了。
> 这不是代码问题，也不是防火墙问题 —— 是 DNS 里少了一条记录。

## 1. 证据

在 5 个公共 DNS（DNSPod 119.29.29.29、阿里 223.5.5.5、Google 8.8.8.8、Cloudflare 1.1.1.1、114.114.114.114）上查询 `seekbbs.cn`，**全部返回 `ENODATA`**：

```
A    seekbbs.cn     : ENODATA      ← 域名存在，但没有 A 记录
A    www.seekbbs.cn : ENOTFOUND   ← 这个子域压根不存在
NS   seekbbs.cn    : coat.dnspod.net, alcohol.dnspod.net   ← 域名本身活着
SOA  seekbbs.cn    : serial=1792428047                      ← 权威解析正常
```

对照 `whalerealm.top` 是正常的（`104.21.47.240` / `172.67.174.139`）。

`ENODATA` 和 `ENOTFOUND` 的区别很关键：
- `ENOTFOUND` = 域名不存在或没有 NS 委托
- **`ENODATA` = 域名在、NS 在、权威服务器在，但你要的那个记录类型一条都没有**

所以浏览器报的是“无法解析主机”，而不是 404 或连不上。

## 2. 服务器这一侧已经修好了

| 项 | 改动前 | 现在 |
|---|---|---|
| `jingyu.service` | inactive + disabled | **active + enabled** |
| 数据库 | 已删除 | 5.5 MB 精简库（境外生产库一致性快照，跳过 README 正文缓存） |
| nginx 80 | **整站 307 跳境外** | **自己服务站点**：`/`、`/api/`、`/ws`、`/admin/`、`/whale/`、`/uploads/` |
| 前端产物 | 10-26 旧版（`app.65b12c3f.js`） | 与境外同版（`app.8181bd0b.js`） |
| 后端代码 | 10-26 旧版 | 与境外同版（含举报通道、插件审核、下架过滤） |
| 下架条目 | 会出现在列表里 | 21 条已下架条目在境内也查不到 |
| `SITE_ORIGIN` | `http://43.142.153.74` | `http://seekbbs.cn` |

**实测**（从中国网络直连 IP）：

```
http://43.142.153.74/                          → 200  9595 B  0.073 s
http://43.142.153.74/api/plugins?q=dsh-blender → 200  4416 B

```

对照境外 `whalerealm.top` 的 TTFB 是 **0.93 s**，境内是 **0.07 s**，快 13 倍。

## 3. 你要做的唯一一件事

去 DNSPod 控制台给 `seekbbs.cn` 加 A 记录：

| 主机记录 | 记录类型 | 记录值 | 线路 | TTL |
|---|---|---|---|---|
| `@` | A | `43.142.153.74` | 默认 | 600 |
| `www` | A | `43.142.153.74` | 默认 | 600 |

或者用脚本（需要 DNSPod Token）：

```bash
# 1) 取 Token：https://console.dnspod.cn/account/token
# 2) 跑一次（脚本会先列出可见域名与现有记录，再创建，最后轮询验证）
DNSPOD_ID=<ID> DNSPOD_TOKEN=<Token> bash tools/dnspod-add-a.sh

# www 子域
DOMAIN=www.seekbbs.cn DNSPOD_ID=... DNSPOD_TOKEN=... bash tools/dnspod-add-a.sh

# 只看不改
DNSPOD_ID=... DNSPOD_TOKEN=... DRY_RUN=1 bash tools/dnspod-add-a.sh
```

为什么我不能代做：本机与两台服务器上都查过——`tccli` 未安装，`env` 无 token，`/etc`、`~/.bash_history`、`/var/www/jingyu/server/.env` 里 `dnspod` / `secret_id` / `tencentcloud` 零命中。加 DNS 记录必须有账号级授权。

## 4. 加完之后

1–2 分钟内（TTL 600）`http://seekbbs.cn/` 就能打开。第一次打开会是 HTTP —— 页面功能全都能用，只是浏览器地址栏会显示“不安全”。

然后按顺序补 HTTPS：

```bash
# ① 腾讯云轻量控制台 → 防火墙 → 放行 TCP:443
#    （本机 ufw 已 ALLOW、nginx 已监听 443，但从公网连不上 = 拦在控制台）

# ② 签证书（certbot 已装好，1.21.0）
ssh ubuntu@43.142.153.74
sudo mkdir -p /var/www/certbot
sudo certbot certonly --webroot -w /var/www/certbot \
  -d seekbbs.cn -d www.seekbbs.cn --agree-tos -m <你的邮箱> --non-interactive
```

签发成功后要改**两处**（顺序不能反，否则 443 会先挂）：

```bash
# ① jingyu-443.conf：把自签证书换成 LE 证书，并把「一律 301 回 HTTP」改成正常服务
# ② .env：SITE_ORIGIN 改回 https://seekbbs.cn 后 restart
#    （现在故意设成 http，因为 443 还没通；若提前设成 https，cookie 会带 Secure 标志，
#      浏览器在 HTTP 下直接丢弃它 → 「登录成功、刷新变游客」）
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 6. 顺带说清一件事：现在两台都在写

境内库是境外生产库的**一次性快照**（`sqlite3 .backup` + 只搬业务表）。两台机器的库是两个**不同的物理文件**，所以不会出现“同一文件被两边同时写”的问题。

但从现在起，用户在境内注册、发帖、举报，数据只落在境内；境外那份不会再同步过来。等你确认境内稳定后，应该二选一：

- **A（推荐）**：境内成为唯一写入源，境外只保留静态镜像；
- **B**：境外继续当唯一写入源，境内改回反向代理（但那样又回到“页面在境外”的老问题）。

这个取舍要等你先能用上站点再决定，现在不动。
