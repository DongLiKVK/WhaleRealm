# v2 · 无障碍与键盘可用性评审（WCAG 2.2 AA）

范围：index.html 全文、js/app.js 的 navHTML()/feedPage()/threadPage()/render()/toast()/事件委托/fab 绑定、css/app.css 的 :focus-visible / prefers-reduced-motion / 控件尺寸。静态审读，未跑 CDP。

## 必修

### 1. 没有 `main`，7 个路由没有 h1，入口页 h1→h3 跳级
**问题**：`#app` 直接吐 `<div class="wrap">`，全站无 `<main>`，屏读用户拿不到「跳到主内容」；h1 只在首页与条目页出现，论坛/帖子/库/空间/认领/上传/政策全缺，标题导航失效。**证据**：index.html:15；app.js:315/425/534/716/817/826/1054/1145/1254 均为 `'<div class="wrap">'`；h1 仅 app.js:197、544；threadPage 用 h2（app.js:1149）；entryBody 在 h1 后直接 h3（app.js:647）。**改法**：不动类名，只改 render() 一处注入 main，再按下表提级：

```js
// app.js:1407
app.innerHTML = navHTML() + '<main id="main" tabindex="-1">' +
  ((switched||enterNext)?enterWrap(body):body) + '</main>' + FOOTER + lightboxHTML() + tabbarHTML();
```

| 位置 | 现在 | 改成 |
|---|---|---|
| app.js:426 marketPage | `<span class="t">插件条目库</span>` | `<h1 class="t">` |
| app.js:1149 threadPage | `<h2>` | `<h1>` |
| app.js:719 claimPage | `<h2>` | `<h1>` |
| app.js:1256 spacePage | `<h2>` | `<h1>` |
| app.js:1056 forumPage | 无 | `<h1 class="sr-only">论坛</h1>` |

| app.js:647/652/655 entryBody | `<h3>` | `<h2>`（消掉 1→3 跳级） |

**风险**：css 全文无 `#app` 规则，多一层块级盒不影响布局；48 项 `_smoke.cjs` 按类名断言（.logo/.nav-links/.thread.trow），58 项 `_v6.cjs` 按 `[data-act]` 取元素，均不校验父子层级，不动类名即零碰撞。仅 `_rv_probe.cjs` 的 landmarks 计数会变，那是探针不是断言。

### 2. 键盘方案：统一补是已选对的路，但有一处嵌套交互与全站缺 aria-pressed
**问题**：`enhanceA11y()` 已给非原生 `[data-act]` 统一补 role=button + tabindex=0（app.js:1388-1395），delegated keydown 已处理 Enter/Space 并 preventDefault（app.js:1763-1769）—— 这条路对，别改成逐个换标签。真洞是：`.pl-card` 整体是 role=button（app.js:387），里面又套了真按钮 install（app.js:397），嵌套交互；且 like/install/fav 全是纯图标切换，没有 aria-pressed，屏读查不到当前态。**改法**：

```js
// ① 把点击目标从卡片下移到标题，解开嵌套（app.js:387/390）
'<div class="pl-card" style="--grad:'+p.grad+'">'           // 去掉 data-act="pl"
'<span class="pl-name" data-act="pl" data-id="'+p.id+'">'    // 390 行加 data-act
// ② 切换态补 aria-pressed（app.js:256 like / 397 install）
'<button class="act '+(liked?'liked':'')+'" data-act="like" data-pid="'+p.id+'" aria-pressed="'+liked+'">'
```

**风险**：①会让整卡点击区变成只有标题可点 —— 需给 `.pl-card` 补 :hover 保持手感，且 `_v6.cjs` 若有「点卡片进条目页」的坐标断言需复核（它按 `[data-act="pl"]` 定位仍能找到，只是命中点在标题上）。②纯加属性，无断言依赖。

### 3. 焦点管理：每次 render 都掉到 body，不只切路由
**问题**：render() 全量重写 `app.innerHTML`（app.js:1407），被聚焦节点直接销毁，焦点静默退回 body；`render(true)` 的点赞（app.js:1621）、安装（1637）、展开评论（1643）同样丢焦点，键盘用户点一次赞就要从页首重新 Tab 一遍。**改法**（与平滑滚动冲突：`scrollTo({behavior:'smooth'})` 会和 focus 的自动滚动抢，必须 preventScroll）：

```js
if (keep) window.scrollTo(0, y);
else {
  window.scrollTo({ top: 0, behavior: scrollMode() });        // 1423
  const m = document.getElementById('main');
  if (m) m.focus({ preventScroll: true });                    // 只切路由时
}
// 同页重绘：按 data-act 归还焦点
const back = document.activeElement && document.activeElement.dataset.act;
if (!switched && back) { const n = qs('[data-act="'+back+'"]'); if (n) n.focus({ preventScroll: true }); }
```

**风险**：`main[tabindex="-1"]` 让「切页后第一次 Tab」从 main 内第一个可聚焦元素开始（符合预期）；若 48 项里有依赖 `document.activeElement` 的断言，改后需重跑 `node shots/_smoke.cjs`。

### 4. 焦点可见：有统一环，但顶栏与选中芯片上是同色环；两个搜索框完全无焦点
**问题**：app.css:832 有统一 `:focus-visible`，833 夜主题换 `--brand-2`；但 1267 那条 `[data-act]:focus-visible` 没有夜间覆盖。真问题是颜色：顶栏 `.nav-links a`（app.css:80-85）底色是 `#0a4a86→#1775c8` 渐变，环色 `--brand` 正是 `#1775c8` → 1:1 不可见；`.chip.on`（app.css:437）实底同为 brand 渐变，同样 1:1。夜主题 `#3f9de8` 对 `#1775c8` 约 2.1:1，仍够不到 1.4.11 的 3:1。另：`.mkt-search input`（app.css:442 `outline:0`）与 `.cin`（app.js:264 内联 `outline:0`）没有任何 `:focus`/`:focus-within` 补偿，插件库与论坛搜索框完全无可见焦点。aria-label 只有 fab-write/fab-top（index.html:19-20）和 `.sw`（app.js:763）；主题键、铃铛只有 `title`（app.js:168-169），且铃铛里 `.dot-badge` 的「3」会被读进按钮名。**改法**：

```css
.nav a:focus-visible,.nav-links a.on:focus-visible,.chip.on:focus-visible{
  outline:2px solid #fff; outline-offset:2px; box-shadow:0 0 0 2px #0a4a86; }
.mkt-search:focus-within{border-color:var(--brand);box-shadow:0 0 0 3px rgba(47,156,244,.18)}
```

```js
'<button class="icon-btn" data-act="theme" aria-label="切换白天 / 夜间" title="…">'
'<button class="icon-btn" data-act="pop" data-pop="notice" aria-label="消息'+(S.noticesRead?'':'，3 条未读')+'">…<i class="dot-badge" aria-hidden="true">3</i>'
```

**风险**：白环 + 深蓝投影的双层环不改尺寸，不影响布局断言；`aria-hidden` 加在角标上零风险。

### 5. 状态播报：live region 是懒建的，首次 toast 大概率被吞
**问题**：`toast()` 在第一次调用时才 `createElement('div')` 并同时塞文本（app.js:116-125）。live region 必须在内容变化前已存在，一次性创建+插入常被屏读忽略。更漏的是：`tlike`（app.js:1624-1627）、`flike`（1629-1633）、`expand`（1640）、`upver/upbreak/chk`（1566-1576）完全静默；`sha`/`copyv` 复制没等 Promise，clipboard 被拒时照样报「已复制」（app.js:1498-1500、1517-1520）—— 既漏报也谎报。**改法**：

```js
// 启动时先建空容器（沿用 116-122 的 aria-live/role，只是提前）
const toastWrap = document.createElement('div');
toastWrap.className='toast-wrap'; toastWrap.setAttribute('aria-live','polite');
toastWrap.setAttribute('role','status'); document.body.appendChild(toastWrap);
// 复制按真实结果再播
(navigator.clipboard.writeText(v)||Promise.reject())
  .then(()=>toast('sha256 已复制','📋'))
  .catch(()=>toast('复制失败，请手动选中','⚠️'));
// tlike 补一句
toast(S.liked.has(k) ? '已取消赞' : '已点赞', '❤️');
```

**风险**：容器提前常驻后，`_smoke.cjs` 里「toast 出现」类断言（按 `.toast` 子节点数判断）仍成立；若有断言「初始无 .toast-wrap」会翻，改后先跑一次。

### 6. 点击目标 < 24×24（2.5.8）
**证据**（字号×1.65 + padding 估算）：`.tag-plain.click`（app.css:556，1px 7px/11px）≈20px，论坛热标签 app.js:1068 可点；`.dl-info .sha`（932）≈20px，app.js:581 可点；`.post-more`（309，2px 6px/16px）≈21px；`.pl-install`（470，3px 12px/11.5px）≈21px；`.sorts button`（444，3px 8px/12px）≈22px；`.floor-actions button`（531，`padding:0 2px`/11.5px）≈19px；`.up-file .uf-x`（1091）≈23px；`.pop-hd .mini`（app.js:177 `readall`，1px 14px/12px）≈21px。

顺带两个同源缺陷：`.post-more`（app.js:253）是 `<button title="更多">⋯</button>` 却既无 `data-act` 也无监听 —— 屏读会播报一个点了没反应的按钮；`.cmt .clike`（app.js:242）挂着 `cursor:pointer` 但同样无 `data-act`，是假可点。二者要么补行为，要么降级成纯文本。

达标：`.icon-btn` 34×34（97）、`.fab` 44/40（732、746）、`.lightbox .x` 38（727）、`.chip`≈26（431）、`.rail-item`≈35（164）、`.avatar-btn`≈36（108）。**改法**：除 `.sorts button` 外一律用伪元素扩热区，视觉不变：

```css
.tag-plain.click,.dl-info .sha,.post-more,.pl-install,.floor-actions button,.up-file .uf-x,.pop-hd .mini{position:relative}
.tag-plain.click::after,.dl-info .sha::after,.post-more::after,.pl-install::after,
.floor-actions button::after,.up-file .uf-x::after,.pop-hd .mini::after{
  content:"";position:absolute;left:50%;top:50%;translate:-50% -50%;min-width:24px;min-height:24px;width:100%;height:100%; }
.sorts button{padding:6px 8px}   /* gap 只有 2px，伪元素扩热区会互相覆盖 */
```

**风险**：`.sorts` 那组必须用真实 padding，否则点「热门」会命中「最新」；伪元素热区若溢出到相邻可点元素同样会误点 —— 落地后用 `shots/_v2probe2.cjs` 那套 `elementFromPoint` 点测复核。

## 建议

### 7. prefers-reduced-motion：CSS 很全，漏的是 JS 平滑滚动
CSS 侧 845-852 已把 `--dur-*` 压到 1-90ms、`animation-duration:1ms`、hover 位移清零，1262-1264 再清一批 transition；灯箱与 toast 的 transform 也在 851 关掉。**真漏**：`behavior:'smooth'` 是 JS 参数，任何媒体查询都管不到 —— app.js:1423、1585、1611、1647、1787 五处，减弱动效用户点「查看全部评论」「回顶部」「写动态」仍被强制滚几屏。`.pop` 的 translateY+scale 过渡（app.css:118）不在 849-851 名单，只是被压到 90ms，属可接受。

```js
const RM = matchMedia('(prefers-reduced-motion: reduce)');
const scrollMode = () => RM.matches ? 'auto' : 'smooth';   // 五处统一替换
```

**风险**：26 项 `_motion.cjs` 含 reduced-motion 断言，按 README:34 它测的是 CSS token 与降级，不测 JS 滚动；改后仍需跑一次确认。

### 8. 灯箱缺 dialog 语义与焦点归位
app.js:1279-1285 无 `role="dialog"`/`aria-modal`，开着时背景仍可 Tab 进入，关闭后焦点不回到触发图。补 `role="dialog" aria-modal="true" aria-label="图片查看"`，open 后 focus `.x`，close 后焦点回 `[data-act="lb"]`。

### 9. 导航当前项无 aria-current，sr-only 工具类根本不存在
app.js:163、1339 只有 `.on` 视觉态，缺 `aria-current="page"`；`.sr-only` 在全 css 中不存在，第 1 条的隐藏 h1 需要它（4 行）：

```css
.sr-only{position:absolute;width:1px;height:1px;margin:-1px;padding:0;overflow:hidden;clip:rect(0 0 0 0);white-space:nowrap;border:0}
```

## 不建议做

1. **不要把 div/span 逐个换成 `<button>`。** enhanceA11y（app.js:1388-1395）已统一补 role/tabindex，keydown（1763-1769）已处理 Enter/Space 且 preventDefault 防滚页，语义已等价；换标签会改掉 `.rail-item`/`.notice`/`.hot-item`/`.pl-card` 的结构，而这些类名正是 48+58 项断言的取元素依据，收益为零、返工面却是全套。
2. **不要给装饰元素补 tabindex 或撑到 24px。** `.tag`（app.css:496）、`.dot-badge`（103）、`.hot-flag`（479）不可点，2.5.8 不适用；扩大只会挤坏已有信息密度。
3. **不要引入 axe-core 或任何 a11y 运行时库。** 项目卖点是零依赖无构建（README:183 自称「语义化标签 + aria-label + prefers-reduced-motion」）；一次性 CDP 探针即可，`shots/_aria.cjs`、`shots/_rv_probe.cjs` 已经是这个形状，扩成 `_a11y3.cjs` 比引库更贴合。
