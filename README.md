# 鲸域（仿 QQ 空间风格前端）

一个零依赖、零构建的静态前端演示：把「DSH 开发者社群」做成 QQ 空间那种蓝白社交界面 —— 更新日志流 + 插件条目库 + 社群 + 聊天 + 个人空间，
外加一条完整的「条目 → 认领 → 授权 → 上传 → 下架」插件治理链路。
纯手写 HTML / CSS / JS，前端无框架、无 npm 依赖，双击 `index.html` 就能看。

需要真正的登录、发帖、上传时，配 `server/` 里那套可选后端（Node + SQLite），
用 `node dev-server.mjs` 一条命令把前端与接口起在同一个源上。

### 三条硬规矩

1. **不双向同步 SQLite。** 两台同时读写同一个库文件，最后一定是某台的写入被静默丢弃。要同步只能「一台写、另一台只读副本」。
2. **不用 scp/rsync 覆盖生产 db。** 传之前 WAL 里未 checkpoint 的事务会丢，传的时候进程还在写会拿到半截库。备份要用 `better-sqlite3` 的 `backup()`（在线热备，WAL 安全），现成的：`deploy/jingyu-backup-db.sh`。
3. **三台不要各自随机 `JWT_SECRET`。** 当前境内/境外共用同一个（sha256 指纹 `480ae933`），本地用代码兜底值。随机化会让每次重启踢掉全部会话。

## 快速开始

### 只有前端

```bash
# 方式一：直接打开
start index.html

# 方式二：起个静态服务器（推荐，hash 深链更稳）
python -m http.server 8777 --bind 127.0.0.1
# 打开 http://127.0.0.1:8777/index.html
```

纯静态时页面自己带一份演示数据（`js/data.js`），所有交互都能点，只是**没有登录、不能发帖** ——
脚本会去打 `/api/*`，静态服务器不认这个路径，于是顶部挂出「离线 · 请登录」的胶囊。
（演示账号登不上去、提示「连不上服务端」，就是走到了这一条；见下面「连后端跑」。）

### 连后端跑（要登录、要发帖就选这个）

```bash
cd server && npm install && npm run seed && cd ..
node dev-server.mjs
# 打开 http://127.0.0.1:8777/
```

`dev-server.mjs` 是一个零依赖的小服务器，只做三件事：把仓库根目录当静态站点、把 `/api/*` 反代到
`127.0.0.1:3000`、把 `/ws` 的升级请求转发过去。它还会顺手把后端拉起来（已经在跑就直接复用），
所以一条命令就能全栈跑通。

**为什么要多这一层，而不是直接开两个端口**：前端的 `fetch` 用的是 `credentials: 'same-origin'`，
登录态是 httpOnly Cookie。浏览器 8777、接口 3000 属于两个源，Cookie 不会跟着走 —— 现象就是
「登录接口返回 200，刷新一下又变回游客」。反代之后浏览器只看到一个源，Cookie 才能正常往返。

演示账号（`npm run seed` 灌进去的）：

| 邮箱 | 密码 |
| --- | --- |
| `demo1@jingyu.local` ~ `demo8@jingyu.local` | `jingyu1234` |

数据库落在 `server/data/jingyu.db`（SQLite，已在 `.gitignore` 里）。想重来一遍就删掉这个文件再
`npm run seed`。

改端口用环境变量：`DEV_PORT=8000 node dev-server.mjs`；只想起前端不拉后端就加 `DEV_NO_API=1`。

**登录不上时按这三条对号**（错误文案不一样，能直接定位）：

| 你看到 | 意思 | 怎么办 |
| --- | --- | --- |
| 「连不上服务端，检查网络后重试」 | `/api` 没人接 | 你大概在用纯静态服务器，换成 `node dev-server.mjs` |
| 登录成功但刷新就变游客 | 跨源丢了 Cookie | 别用两个端口，走 `dev-server.mjs` 的同源反代 |
| 「这个邮箱还没注册」 | 后端通了，但库里没这个账号 | 还没跑 `npm run seed`，或者邮箱打错了 |

另外后端有「手机 / 电脑各一条会话」的规则（v46）：同一账号在**同一类设备**上再登录会回 409，
登录框会多出一个「顶掉电脑上的登录 / 顶掉手机上的登录」按钮，点它才会顶替那一台；
手机与电脑之间互不影响。这是设计如此，不是故障。

## 标志：鲸尾

站点标志是一条鲸鱼尾鳍**线稿**：单条开放 SVG 路径（56 个锚点、只描边不填充，没有外部图片、没有字体图标），定义在 [js/app.js](js/app.js) 顶部的 `TAIL_D`，由 `tail(size, sw)` 生成 `<svg viewBox="0 0 64 64">`。颜色走 `currentColor`（由 CSS 的 `color` 决定），线宽由每次调用传入：导航 `tail(22, 5.2)`、头图 `tail('100%', 2.3)`、页脚 `tail(13, 6.8)`。

尾巴**顺时针转 9°**：路径本身按未旋转形态归一化（包围盒 `5.71~58.29 / 6.22~57.78`，关于 `(32,32)` 居中），旋转由内层 `<g transform="rotate(9 32 32)">` 施加 —— 旋转原点就是图形中心，要改角度只改这一个数字（favicon 里的 data URI 同步改）。

**为什么是描边而不是填充**：原稿是单线稿，强行闭合成填充后在 16px 下会糊成一个色块；描边版仍能看出「V 形分叉 + 尾柄」。因此导航那枚用了 5.2 的线宽（原图按比例只有约 1.95），小尺寸下主动加粗才不散。

**路径怎么来的**：取源图蓝色蒙版 → Zhang-Suen 细化取中轴 → 端点间最长 BFS 走线 → 端点沿切线外推 15px 补回半笔宽 → 等距重采样 600 点 → 滑动平均平滑 → Douglas-Peucker（`eps=3.0`）→ Catmull-Rom 转三次贝塞尔。改形状重跑该脚本即可，`js/app.js` 里的 `TAIL_D` 就是这条流水线吐出来的那条路径。

favicon 是 [index.html](index.html) 里的 data URI，改 `TAIL_D` 时需要手动同步同一串 path。

### 标签页：linux.do 风格的标签目录（v24）

参考 linux.do 的 `/tags`（Discourse 标准实现）移植，落点是新路由 `#/tags`：

- **数据来源**：唯一真源是 `js/data.js` 的 `tagGroups`（8 组 43 个标签，每组 `{id, name, desc, tags}`）。每个标签的**话题数现算**，走既有的 `tagCountOf(tag)`（池子 = `threadPool()` = 静态 `threads` + 本机新帖），页面上不写死任何数字；加一个标签 = 往某个组的 `tags` 里加一个词，计数 / 搜索 / 分组 / 深链全部自动跟上。
- **文件**：新增 `js/tags.js`（约 13 KB，暴露 `window.TagsPage = { html, collect, sections, hit, SYSTEM }`；只吃 `{S, esc, groups, cloud, pool, tagsOf, count, threadRow, threadCount}` 一组宿主助手，不直接读全局，所以能在 Node 里单测折叠逻辑）；`js/app.js` 只加路由与动作钩子（`tagsPage()`，以及 `pageHTML` / `hashOf` / `applyHash` / `PUBLIC_ROUTES` 各一行；动作 `tagtoggle` / `tagclear` / `tagmode` / `tagmore` / `tagqclear` / `tagsel` / `tagsopen`）；样式是 `css/app.css` 末尾的 v24 段落；`index.html` 在 `app.js` 之前加一行 `<script src="js/tags.js">`（构建脚本按 index.html 的引用自动改名，不用手工登记）。
- **入口**：顶栏「标签」，以及社群左栏「热门标签」卡底部的「全部标签 ›」。
- **交互**：点标签即筛（结果区就地出帖子行）；选第二个起变成**组合浏览** —— 默认「全部满足」（交集），可切「任一满足」（并集）；已选条能单个 ×、能一键「在社群里看 ›」把组合带去社群列表（社群页工具栏下方同步出现同一条可删条）；搜索按名字过滤并实时报命中数；单组超过 14 个标签先折叠，点「显示全部 N 个 ›」展开。
- **深链**：`#/tags/<标签>/<标签>…`（`encodeURIComponent` 编码、最多 12 个、顺序 = 点选顺序），刷新 / 分享 / 直接粘贴都能还原选择；从别的页面进来时组合规则复位成默认的交集。
- **口径**：卡头的「N 个话题」与右栏「标签概览 · 话题总数」同源（池内话题数）—— 一篇帖子挂三个标签只算一篇，同一页上不会出现两个互相打架的数字。
- **风格与兼容**：全部走站内变量（`--card` / `--line` / `--brand` 等），夜间自动成立；≤1240px 左栏入口变横排，≤760px 搜索框整行、已选条横向可滑。

## AI 排行：两份真实榜单，各出全球与纯国内两张（v39）

顶栏第六格「AI排行」进的是 `#/rank`。v37 起不再手写分数，v38 起**两个数据源并排**，v39 把第二张榜从 Epoch ECI 换成 LiveBench（Epoch 的数据文件与抓取器已一并删掉）：

| 数据源 | 抓取来源 | 生成物 | 抓取器 | 量纲 |
| --- | --- | --- | --- | --- |
| LiveBench（默认板，开关排最左） | <https://livebench.ai/#/> | `js/livebench-data.js` | `tools/fetch-livebench.mjs` | 0–100 量级 |
| AA 智能指数 | <https://artificialanalysis.ai/zh/leaderboards/models> | `js/rank-data.js` | `tools/fetch-rank.mjs` | 0–60 量级 |

`js/rank.js` 只负责排序与渲染（`window.AIRank`，与 `js/tags.js` 同一套约定：不读全局，宿主递 `{ S, esc }`），`js/app.js` 只接线与三个点击动作（`rkscope` / `rksort` / `rkboard`）。两个数据源的排序键不通用（AA 是 `code`，LiveBench 是 `coding`），所以各存一份：`S.rankSort` 与 `S.rankLbSort`，切榜时互不干扰，也不会把对方的键判成非法值。

- **两套分数不是一把尺子**：AA 的智能指数是 AA 自算的 0–60 量级综合分；LiveBench 的总分是七个 suite 的算术平均（0–100 量级）。**从不换算、不加总、不互相排名** —— 页面上那排开关旁边就写着这句话，免得读者拿 88.0 和 57.6 直接比大小。
- **数据源开关写进地址栏**：开关从左到右是 **LiveBench → AA 智能指数**，页面默认落在 LiveBench。`#/rank`（LiveBench 全球）· `#/rank/cn`（LiveBench 国内）· `#/rank/aa`（AA 全球）· `#/rank/aa/cn`（AA 国内）；老链接 `#/rank/lb`、`#/rank/lb/cn` 照样收。解析在 `applyHash()`（`seg[1]` 认 `lb` / `aa`，再往后一格认 `cn`），拼回在 `hashOf()`（LiveBench 是默认板，所以它不带段）；排序维度仍然只在内存。

### 一、LiveBench 那张榜（默认板，开关排在最左）

- **一份数据，两张榜**：抓回 49 条模型，`g === 'cn'` 的 **13 条**是纯国内榜（`#/rank/cn`；老的 `#/rank/lb/cn` 也照收），开放权重 19 条挂「开源」徽章。同一个渲染函数、同一份数据；切 tab 写进地址栏，刷新 / 分享都能停在那一张榜。
- **总分不自己加权**：LiveBench 页面上的 OVERALL 就是七个 suite 的算术平均 —— 抓取器用最小二乘复核过（七项权重全 ≈0.1429、合计 1.000、残差 ≤0.06），所以 `ov` 由七个分项现算；体检脚本每次还会再复算一遍（偏差 > 0.15 直接报错）。这也是这张榜没有「权重」可讲的原因。
- **七列都是原始 suite**：长任务 Long Agentic / 推理 Reasoning / 代码 Coding / 浏览 Browser / 分析 Data Analysis / 研究 Research / 设计 Design。中文名压到 2–3 字是因为列头只有 40 像素，英文全名放在悬停里。
- **缺考就是缺考**：CSV 里的 `n/a` 记成 `null`，格子显示灰色 `—` 并带 title「LiveBench 这一项是 n/a —— 这个模型没跑那个 suite」；总分只按有分的项平均，**不补零、不内插**（补零会把缺考的模型直接压到底部，那是编造出来的差距）。
- **进度条按百分制**：`bar100(v) = v`。AA 那张用 `v / 60` —— 两张榜各自归一，条长只在本榜内可比。
- **排序 chip 八个**：总分 + 七个 suite。空值永远垫底（先比有没有分，再比分数，再比名字）。前三名那三张卡一直显示，副行跟着排序维度走（按代码排就写「代码 97.7 · 推理 91.7」）。
- **窄屏列收**：1300px 十一列（名次 / 模型·机构 / 总分 / 七个 suite / 输出价）；1180px 收「浏览 / 研究 / 设计」；900px 再收「长任务 / 分析」，只留「推理 / 代码」；760px 留四列「名次 / 模型 / 总分 / 输出价」。**AA 那张的 900px 规则要带 `:not(.rk-board-lb)`**，否则会把这张榜的 suite 一并收掉。
- **没有「变化」列**：LiveBench 每期只发当期一份 CSV，没有可对比的上一版名次，所以这张榜不摆一根横杠凑数（整列含表头一起不渲染）。
- **国家归属是本站人工映射**：`models.json` 只有 `organization`（16 家），没有国家字段；`tools/fetch-livebench.mjs` 的 `ORG_COUNTRY` 表把 30 个机构名映射成两字代码，认不出的记进 `unmappedOrgs` 且 `g = null`（不进国内榜）。这一点和 AA 那张同办法 —— 两家上游都没给国家。
- **空数据有话说**：`js/livebench-data.js` 缺失时不会白屏，页面上直接写「跑 `node tools/fetch-livebench.mjs` 生成它，再把 script 放进 index.html」。

### 二、AA 智能指数那张榜

- **一份数据，两张榜**：抓回 272 条原始模型，合并同一模型的多推理档（77 条）、丢掉没有智能指数的（5 条），保留 **190 条**；其中 `g === 'cn'` 的 **53 条**就是纯国内榜。`#/rank/aa/cn` 用 `scope === 'cn'` 过滤 —— 同一个渲染函数，不维护两套页面；切 tab 写进地址栏，刷新 / 分享都能停在那一张榜。
- **不再自算综合分**：`total` 就是 AA 的 `intelligenceIndex`（四舍五入到 0.1）。以前那套五项加权 `W` 已删掉 —— 谁排第一该由数据源说，不由本站的权重说。
- **五个分项都是 AA 的原始评测**：专家难题 HLE / 科学推理 GPQA Diamond / 代码 SciCode / 长文 AA-LCR / Agent τ²-bench（AA 的 0–1 小数统一 ×100 记成百分制）。实测覆盖率：HLE 189/190 · GPQA 166/190 · AA-LCR 180/190 · τ² 116/190 · SciCode 97/190；缺的格子显示灰色 `—` 并带 title「AA 未收录这项分数」，不补零、不内插。
- **排序不写进地址栏**：六个 chip（智能指数 / 专家难题 / 科学推理 / 代码 / 长文 / Agent）是页内临时选择（`S.rankSort` 只在内存）。空值永远垫底（先比有没有分，再比分数，再比名字）；选非智能指数时，前三名那三张卡会收起来。
- **窄屏按列收，不横滚**：表格是 div 网格 + `--rk-cols` 变量，头行与数据行共用同一套轨道。1300px 九列（名次 / 模型·机构 / 智能指数 / 五个分项 / 输出价）；1180px 收起「长文 / Agent」；900px 只留「智能指数」；760px 留四列「名次 / 模型 / 智能指数 / 输出价」—— 手机上价格比「变化」有用。**头行格子必须和数据行一起带 `data-dim` / `rk-h-price`**（v36 栽过：只写行内单元格会让十个表头格子挤进四条轨道、折成三行）。
- **「变化」列会自动收起**：`d` 只在「上一版快照的日期与这一版不同」时由两版名次相减算出；首抓或同一天重抓都没有上一版，整列（含表头）加 `rk-no-delta` 收起 —— 而不是给 190 行各挂一根横杠。
- **入口两处**：顶栏第六格；`FOOTER` 底部导航里那条「AI 排行」—— 760px 以下顶栏导航整体隐藏，手机只能从页脚进。
- **访客可看**：`PUBLIC_ROUTES` 里有 `'rank'`。漏了这一步会被进站闸门直接弹回 `#/login`（第一次实测就是这个现象），榜单是公开数据，没理由拿账号当门槛。
- **夜间主题**：六条覆盖（头图 / 前三卡 / chip 选中 / 行悬停 / 开源徽章），断网也成立（不引外部图表库）。

### 数据来源与时效（说实话的那部分）

元数据只有一处真源（`js/rank-data.js` 的 `meta` 与 `js/livebench-data.js` 的 `meta`，`js/rank.js` 分别读成 `SNAPSHOT` 与 `LB_SNAPSHOT`），页面上的「数据 / 抓取时间 / 原始条数」全从它们读 —— 两张榜各读自己那份，不会串：

| 字段 | 当前值 | 含义 |
| --- | --- | --- |
| `source` | `https://artificialanalysis.ai/zh/leaderboards/models` | 唯一抓取来源 |
| `mode` | `scraped` | 页面解析而来，不是人工录入 |
| `fetchedAt` | `2026-10-23T…+08:00` | 抓取时刻，带时区偏移 |
| `asOf` | `2026-10-23` | 这份数据代表哪一天 |
| `cadenceDays` | `7` | 约定每 7 天重抓一版 |
| `nextDue` | `2026-10-30` | 下一版该到的日子，体检脚本用它判过期 |
| `rawModels` / `keptModels` | `272` / `190` | 上游条数 / 清洗后条数 |
| `mergedVariants` / `skippedNoIndex` | `77` / `5` | 合并的多推理档 / 没有智能指数被丢掉 |
| `cnModels` / `unmappedCreators` | `53` / 8 家 | 国内条数 / 机构归属待定 |

LiveBench 那份的 `meta`（当前值）：`source` = `https://livebench.ai/#/`、`sourceData` = `…/data/20261014/table.csv`、`sourceModels` = `…/models.json`、`sourceCost` = `…/cost.csv`、`mode` = `scraped`、`release` = `20261014`、`releaseDate` = `2026-10-14`、`fetchedAt` = `2026-10-23T13:44:04+08:00`、`cadenceDays` = `30`、`nextDue` = `2026-11-13`、`rawModels` / `keptModels` = 49 / 49、`skipped` = 0、`cnModels` = 13、`openModels` = 19、`unmappedOrgs` = 空。

> **这一份的 `asOf` 语义和 AA 不一样**：AA 的 `asOf` 是「抓取日」，LiveBench 的 `asOf` 是「上游那一期的发布日」（2026-10-14），中间差的是抓取时间。体检脚本因此对这份只要求 `asOf ≤ 抓取日`，另外单查一条 `releaseDate === asOf`；页面角标写「数据 2026-10-14」，脚注才写真实抓取时刻。

**没有历史序列**：仓库里只留一份最新数据，`prevAsOf` 有值才说明这次抓取与上一版做过名次对比。想做成时间序列，得先把「每次抓取留一份带日期的快照」这件事建起来（现在是覆盖写）。

**页面会自己说过期**：`staleDays()` / `lbStaleDays()` 各拿今天和自己那份 `nextDue` 比，过期就在角标上挂红胶囊「过期 N 天」，当天挂「今天该更新」—— 两张榜分别判，不会因为 AA 新鲜就把过期的 LiveBench 也当成新的。LiveBench 的周期定 30 天，因为它一期一发（不是每周）。

**体检命令**（零依赖，退出码 1 = 过期或字段被打断，可直接挂 CI）：

```bash
node tools/check-rank-freshness.mjs
```

它对**两份数据各核一遍**：① 文件存在且挂出 `{ meta, models }`、`meta` 六个必需字段齐全、`source` 是 http(s)、`mode` ∈ `scraped` / `hand-curated`；② `nextDue` = `asOf + cadenceDays`（这里抓到过一个真 bug：用 `toISOString()` 做日期加法会把本地零点折回 UTC 前一天，`nextDue` 少一天），AA 还要求 `asOf` 等于 `fetchedAt` 的日期部分，LiveBench 因为 `asOf` 是上游发布日，只要求 `asOf ≤ 抓取日` 且 `releaseDate === asOf`、`release` 是 8 位数字；③ 今天（本机时区）离 `nextDue` 还有几天、是否过期（过期 exit 1、当天 warn）；④ 数据体检 —— AA 看五个分项覆盖率（某列一条都没有 = 上游字段名变了）、取值 0–100、价格非负、模型名重复；LiveBench 看七个 suite 的覆盖率、取值 0–100、价格非负，并把总分按七个分项**复算一遍**（`|平均分 − ov| > 0.15` 即失败，这是页面那句「不需要加权」的硬依据）；⑤ 有没有第二处又写死「快照 20XX-Wxx」或「数据 20XX-XX-XX」；⑥ 一份一句话结论说清「判的是抓取没过期，不是分数准不准」。

**能验证到什么程度**：它能证明「这两份抓取各是某天的、没过约定周期、字段没被打断、页面不会说假话」，**不能**证明「AA / LiveBench 的分数本身对不对」—— 那部分解释权分别在 Artificial Analysis 与 LiveBench，页面上也这么写。

## 插件治理：条目库而不是下载站

这一版把「插件市场」换成了**插件条目库**，核心是把「我们提供的服务」和「作者的授权」分开。每个条目恒在，但取包能力分三档，档位由 `tierOf(p)` 一处算出：

| 档位 | 判据 | 条目页显示 |
| --- | --- | --- |
| **已登记包**（pack） | 作者已认领 + 开启展示（`mirror = auto/manual`）+ 未撤回当前版本 + 已登记文件名 / 大小 / sha256 | 包信息（文件名 · 大小 · sha256）+ 一颗「去作者 Releases 取包 ↗」直达链接 + 三步说明（下载 → 核对 sha256 → `pnpm dsh add ./xxx.tgz`）。**文件在作者仓库，本站不托管、不缓存** |
| **外链**（link） | 作者认领过但关了展示，或本条目撤回过当前版本 | 只有「前往作者仓库」，并写明为什么只给外链 |
| **仅条目**（entry） | 作者未认领、或许可证不允许转载 | 不提供包信息，只留条目正文与原仓库地址；未声明许可证时红字标注 |

三档在列表页用同一枚 `.tier-badge`（`📋` / `↗` / `·`）表示，顶部还有「收录深度」筛选条（全部 / 已登记包 / 外链 / 仅条目）。

**npm 下载胶囊（外链条目的第二颗按钮）**：条目页的动作行里，「去 GitHub 仓库 ↗」右边紧跟一颗「npm 下载 vX.Y.Z ↗」，点开是 `https://www.npmjs.com/package/<slug>`。包名就用 `slug`——DSH 生态的安装约定是 `pnpm dsh add <slug>`，所以这颗按钮给的是读者真正会用的入口，而不是另起一个名字。

这颗按钮**只在包真的存在时才渲染**：6716 条索引里 slug 是按仓库名整理的，实测核对下来 3257 条在 registry 上存在、3459 条 404（作者只挂 GitHub、改了名，或者包是私有的）。无条件拼 URL 会有四成死链，而「点开 404」比「没有这颗按钮」更伤信任。核对结果落在 `plugin_npm` 表（`slug / name / version / found / checked_at`），`GET /api/plugins` 的每条带 `npm: { name, version } | null`，前端 `js/api.js` 的 mapper 白名单里必须显式透传这个字段，否则胶囊会静默消失。

数据怎么来：`cd server && node scripts/check-npm.js --concurrency=24`（`--force` 全量重查、`--ids=1,2` 单查、`--dry-run` 只看不写）。registry 先问 `registry.npmmirror.com` 再兜 `registry.npmjs.org`，两个都超时的条目**不写库**——写 0 等于把「网络抖了」记成「包不存在」。线上由 `jingyu-check-npm.timer` 每周一 06:00 跑一次（`deploy/jingyu-check-npm.{service,timer}`，日志 append 到 `logs/check-npm.log`）。

**「展示」是可收回的**：认领页那个「在条目页展示安装包信息」开关一关，`tierOf` 立刻把该条目降成「仅条目」；「撤回当前版本」则降成「外链」——条目与外链仍在，只是取包入口收起。两个动作都在 `S.mirror` / `S.withdraw` 里，不进 data.js，避免「静态数据说能下、界面说不能下」两套真相。

口径统一：本站看不到别人下载了几次，所以统计一律叫**安装**（`installs`），不叫「下载」；条目页与作者面板的「近 7 天安装」「累计安装」都取自这份演示数据。

**双向聚合**：日志里的插件 chip、社群话题行、帖子楼层都会内嵌 `.plug-inline` 条目小卡，点一下进条目页；条目页底部又把相关讨论列回来。社群与条目库不再是两个孤岛。

**政策页不是弹窗**：转载边界、下架流程、安全声明写成四个章节的长文（含 9 行许可证红线表与两条旧下架记录），左侧锚点目录随滚动高亮。要下架时就指这一页，而不是解释半天。

## 社群：吸取 linux.do 的几条经验

社群页按 [linux.do](https://linux.do/) 的组织方式重做过一轮，抓的是它的信息密度与"社群自治"感：

**分类 + 标签两个维度**，而不是单一标签。分类是粗粒度容器（公告 / 经验分享 / 求助问答 / 插件开发 / 工具与部署 / 灌水闲聊），每条带图标与计数，点一下就是一次筛选；标签是细粒度的横切面（`#冲突排查` `#pnpm` `#Blender` …），以标签云形式放在分类条下面。两者可叠加，排序在最后。

**同名不重复显示**：分类名和主标签是同一个词的情况比想象中多（公告 / 经验分享 / 求助问答），两边都画就会出现同一屏两次同一个维度，还把作者 / 时间挤到换行。判据不是字符串相等，而是 `data.js` 里那张 `catTagAlias` 同义映射表（`{ notice:"公告", guide:"经验", help:"求助" }`）——「经验分享」永远不等于「经验」，靠 `===` 只能碰巧命中「公告」一条。`threadRow` 与帖子详情页的作者行共用 `catDupOf(t)`；附加标签由 `extraTags()` 过滤掉主标签与「置顶」后再取前两个。

**计数只有一个口径**：分类条、左栏、列表三处都走 `threadCountOf(id)` / `tagCountOf(tag)`，池子是 `threadPool() = S.newThreads.concat(threads)`。之前计数只数静态 `threads`、列表却含刚发的帖子，会得到「8 个话题、9 行列表」。

**话题行是信息容器**，不是标题 + 数字：头像 → 徽章区（置顶 / 🔥 / 已解决 / 新）→ 标题（单行省略）→ 摘要（一行 clamp）→ 元信息行（彩色标签、附加标签、作者、时间、最后回复）→ 参与者头像堆叠（重叠 -6px，多出来的折成 `+n`）→ 右对齐统计（回复 / 浏览 / 点赞三行）。

**表情反应取代单一「赞」**：每条主楼与楼层都有 👍🎉💡🔥👀 五个反应，点一下 `S.reacts` 这个 Set 里加键（`帖子id_op`、`帖子id_楼层序号`），选中态换蓝底。比一个数字更能表达"这条有用 / 这条好笑 / 这条值得看"。

**本帖导航 timeline**：帖子详情右栏不是目录树，而是"5 楼里有几楼读过了"的进度条 + 逐楼摘要，点楼号 `scrollIntoView` 并给该楼加 `.flash` 播一次高亮；底部有「返回列表」。长帖里比翻页快。

**社群准则卡**：💚 真诚 / 🤝 友善 / 🧑‍🤝‍🧑 团结 / 🔬 专业，四条，放在右栏而不是塞进页脚 —— 准则要一直在视野里才有约束力。

每条压到**一行**：图标 + 原则名 + 半句补充（前半句该做、后半句「不…」不该做，读起来是一句人话，不需要标题式小标题）：

```
💚 真诚   有话直说，不装懂
🤝 友善   对人客气，不攻击
🧑‍🤝‍🧑 团结   能帮就帮，不藏私
🔬 专业   贴报错原文，不空谈
```

数据在 `js/data.js:415-421`（`guidelines`，每条只有 `icon` / `t` / `s` 三个字段），渲染在 `js/app.js:3282-3290` `guidelineCard()`，样式 `css/app.css:850-858`。三档视口实测卡宽 300/312/406、**卡高 187px**（原三行版 387px，省 52%），四行各 32–33px、`.gl-s` 恒为单行（`ellipsis:0`、`overflow:0`）、页面零横向溢出；浅色与夜间都过（浅色与夜间各测一轮）。

**两个坑**：① 早期版本末尾有 `.gl-foot` 收束语节点时，`.gl-row:last-child` 不再命中最后一行，虚线会多一条 —— 压成一行后已删掉 foot，改用 `.gl-row + .gl-row{border-top}` 只画行间线，天然没有末行问题；② `@media (max-width:1080px)` 把 `.col-side` 改成 `flex-direction:row;flex-wrap:wrap`，此时默认 `align-items:stretch` 会让同排卡片被最高那张拉平（准则卡一度被拉到 357px 高，底部一大片空白），必须显式 `align-items:flex-start`，窄屏 `≤760px` 再改回 `stretch` 让竖排卡片铺满宽度。

![社群列表、帖子详情与 390px 重排](docs/screenshots/forum-showcase.png)

**窄屏重排**：390px 下话题行从「头像 | 正文 | 参与者 | 统计」横排改成两列网格 —— 头像占左列，正文占右列第一行，统计横排到右列第二行（回复 / 浏览 / 点赞一行显示）。标题因此拿到整行宽度，不会只剩三个字；最后回复一项直接隐藏，避免出现以「·」开头的孤立行。

## 设计要点

- **QQ 空间视觉**：顶部渐变蓝导航（`#1f86dc → #5ec7f6`）、圆角白卡片 + 淡蓝底（`#f0f5fa`）、云朵头图、圆角头像、橙蓝撞色按钮，字体走系统中文栈。
- **零素材依赖**：所有头像用 canvas 生成渐变色块 + emoji 的 dataURL（带缓存）；所有配图用 CSS 渐变 + 斜纹 + 假窗口标题栏绘制，不请求任何图片。
- **不用构建**：`index.html` 直接引五个脚本（brand → data → api → auth → app），改完刷新即可；不存在 node_modules。
- **可访问性/性能**：语义化标签、`aria-label`、`prefers-reduced-motion` 降级、事件全部委托在 `document` 上（换页不重绑）。
- **对比度**：全局色板按 WCAG AA 调过（`--brand-ink` 专门承载浅底蓝字，橙色 CTA 用 `--ink-amber` 深色字）；头图/封面这类"固定浅色渐变"区域额外压一层白色薄纱，保证深色模式下文字仍然达标。

## 自动化测试

开发期的验收全部用 Chrome DevTools Protocol 驱动真实浏览器完成（无 puppeteer 依赖）。脚本与截图没有入库 —— 它们写死了本机的 Chrome 路径、端口与产物目录，换台机器 clone 下来也跑不通。这里留下的是**验过什么、怎么验、结果怎么读**，要复现时照着写一个同口径的脚本即可。

**方法**：先起静态服务器，脚本一律连 `http://127.0.0.1:8777/index.html`（个别脚本读 `BASE` 环境变量覆盖）。每个脚本自己起一个干净的 `--user-data-dir`，启动即 `Network.setCacheDisabled`，避免上一轮的 localStorage 与旧 JS/CSS 造成假失败；跑之前先删掉对应的 profile 目录，否则同样会假失败。断言读的是 DOM 几何与计算样式，不靠截图肉眼比对，截图只作留档。

**验过的范围**（按主题归类）：

- **交互与路由**：逐次点击后收集运行时异常；分类 + 标签双维筛选、四档排序、深链与前进后退、灯箱键盘操作、插件安装态、登录 / 注册 / 手机号认证 / 退出全链路。
- **无障碍**：2 主题 × 全路由的真实像素采样对比度（半透明选中底按 alpha 合成算），地标 / `h1` 唯一 / 焦点交接 / 24×24 热区 / `prefers-reduced-motion` 降级 / 关脚本兜底页。
- **响应式**：320 / 390 / 768 / 820 / 1024 / 1100 / 1240 / 1440 八档宽度下的折行与 `scrollWidth` 横向溢出。
- **动效**：时长与缓动 token、进场 / 退场对称、降级档位。
- **人物卡**：三档视口插槽尺寸（±2px）、默认站位与左右边界、拖拽 1:1 位移与四个方向 `hitEdge`、按下不瞬移、松手不回弹、文案区放行指针、滚轮滚动链。
- **随机素材池**：107 段全部进池、106 段带 alpha、逐段可解码、抽样覆盖与相邻重复率；画中画 / 遥控播放 / 下载三个属性必须被关掉，`requestPictureInPicture` 必须被拒。
- **数据口径**：期望值一律从 `js/data.js` 现算（作者下载量榜、标签计数、分类串 `14,2,1,1,1,2,2,1,1,0,1,0,1,1`）再与 DOM 对账，而不是把数字抄死在断言里。

**结果怎么读**：全绿的含义是「断言全过 + JS 运行时报错 0 条 + 对比度不达标 0 处」，三者分开统计 —— 只有脚本异常与 `Log.entryAdded` 里 `source !== 'network'` 的条目才算失败，网络 404 单独计数。

> **没有后端时有些断言必然红**：访客只读（`js/app.js` 的 `GUEST_BLOCK`），发表动态还要走后端 `/api/posts`；`js/auth.js` 的会话只来自 `/api/auth/*`，内存快照刷新即失效。所以点赞 / 评论 / 发表 / 安装态这类写操作，以及「默认已登录」这一条，只有接上 `server/` 才有意义。同理 `API.sync()` 会打三个 `/api/*` 拿到 404，这属于预期。

> **对比度采样前先藏掉 `#api-offline`**：那条胶囊是 `fixed`，全页截图时会被画到当前视口位置，压出假失败。

> **离线提示胶囊的出场规则**：登录 / 注册 / 手机号认证 / 第三方授权四页一律不挂（用户还没进站，顶栏的「离线 · 请登录」已经把没连后端讲清楚了，底部再浮一条就是每次刷新都在最下方多一根横条）；进站后的页面只提示一次、6 秒后自己淡出移除（`js/api.js` 的 `markOffline`，`API._offlineShown` 保证一次加载只挂一次）。

## 无障碍与首屏（v2 加固）

- **地标与标题层级**：`render()` 把页面主体包进 `<main id="main" tabindex="-1">`，导航与页脚在它外面；十四个路由各自的 `h1` 唯一，条目正文的 `h3` 已升 `h2`，不再跳级。测试不需要的标题（社群、个人空间、政策页）用 `.sr-only` 的 `h1` 补语义。
- **焦点交接**：切路由后焦点落到 `main`（读屏从新页面开头念起）；同页重绘按 `data-act + data-id` 指纹把焦点还给刚点的按钮；灯箱关闭后焦点回到触发它的那张图。
- **键盘**：所有 `[data-act]` 的非原生控件统一补 `role="button" + tabindex="0"` 并响应 Enter/Space；焦点环改成「白描边 + 深蓝投影」双层，在蓝底和浅底上都看得见；`↑` 悬浮键隐藏时会退出 Tab 序列。
- **热区**：小于 24×24 的控件（安装、更多、标签、楼层操作、评论赞、全部已读）用 `::after` 把命中区撑到 24×24，**布局盒不变**；排序按钮因为间距只有 2px，改用真实 padding 撑开，避免伪元素互相覆盖。
- **状态播报**：`.toast-wrap` 在启动时就常驻并带 `role="status" aria-live="polite"`，首条提示不会被屏读吞掉；复制成功与否按 `clipboard.writeText` 的 Promise 结果播报，失败会给出「请手动复制」而不是谎报成功。
- **首屏**：`<html>` 里在 `<link rel="stylesheet">` **之前**跑一段内联脚本恢复主题，夜间刷新不再闪白；`html{background:var(--bg)}` 让过卷区跟着主题走；`color-scheme` 让原生滚动条/表单控件跟随主题；`#app` 里放了静态骨架，脚本一加载即被整块替换。
- **无脚本**：`<noscript>` 里给出完整的说明卡（站点是什么、为什么需要 JS、怎么开），并用 `<style>` 隐藏 `#totop` 和骨架。
- **移动端**：`#totop` 与 toast 抬到底栏之上（`calc(58px + env(safe-area-inset-bottom) + 14px)`），不再抢底栏的点击；`.wrap` 底部留 96px；tab 条允许横向滑动且不折行；头图标题在 400px / 480px / 760px 三档分别收字号，320→1024 全宽度都保持单行。
- **✎ 按路由分派**：在帖子页变「回复本帖」（聚焦 `#reply`）、在社群页变「发新帖」、其余页面才回首页写日志 —— 之前一律跳首页，会把打了一半的回复静默吞掉。

## 深海主题与发布页（v8）

### 只挂一个容器类的主题

深海皮肤没有第二套 CSS 变量表，也没有 `html[data-theme="deep"]`。它做的是：`spacePage()` 与 `profilePage()` 的最外层从 `<div class="wrap">` 变成 `<div class="wrap deep">`，然后由 `.wrap.deep { --txt: …; --card: …; }` 在这棵子树里改值。

这么做有三个理由：

1. **深链与刷新**：主题跟着路由走，不需要在 `localStorage` 里记「我现在是什么皮肤」，也不会出现「从空间页退回首页还是深海色」。
2. **`_motion.cjs` 锁着 `:root`**：动效断言要求 `--brand === '#1775c8'`、`--brand-ink === '#0f63b4'`，全站令牌不能动。局部改值既满足动效断言，也让深海页之外的 9 个路由配色一个像素都不变。
3. **磨砂要能拿到变量**：`.wrap.deep .card { background: var(--card) }` 里的 `var(--card)` 在 `.wrap.deep` 作用域内解析成 `rgba(11,32,53,.66)`，于是同一套卡片规则自动变成半透明磨砂，不用重写一遍卡片样式。

**踩过的坑（都已修）**：CSS 变量在**声明处**按 `var()` 求值后再继承，所以 `.side-hd` 这类「自己没有 color、靠继承」的节点，拿到的仍是 `body` 用 `:root --txt` 算出的深色 `#132435` —— 在深底上只有 1.0:1。修法是在 `.wrap.deep` 上直接写 `color: var(--txt)`，并给 `.side-hd` / `.sp-row b` / `.pub-radio-tag` 这类继承型节点显式补 `color`。

### 装饰层不接事件

`.sea-life` 是 `.wrap.deep` 里的第一个子元素，`position:absolute; inset:0; z-index:-1; pointer-events:none`，承载四层装饰：容器顶部的光晕、三条缓慢摆动的光束（`raySway`）、两条横向漂移的暗流（`flowDrift`）、七个从底部上浮的气泡（`bubRise`，各带负延迟所以一进页面就已经在途）、三条横向游过的鲸尾剪影（`swimAcross`，78~96 秒一趟）。

全部是 CSS `@keyframes`，没有 JS 定时器；`prefers-reduced-motion: reduce` 时整层动画 `animation:none`、气泡固定在 `top:50%` 不动。

### 撰稿人：从「访客头像墙」改过来

原来侧栏第二卡是 4 个访客头像 + 时间（`.visitors`）。换成仿 GitHub Contributors 之后：

- **数据是确定的**：`contribOf(uid)` 用 `((name.charCodeAt(1) * 37 + i * 11) % 47) + 3` 算贡献数，同一个人刷新多少次都是同一个数字，不会跳动。
- **方阵**：5 列网格，前 9 人各占一格（头像铺满格子 + 底部半透明数字条），余下折成 `+N` 遮罩格；点头像进对应用户空间。
- **柱状图**：12 根柱子代表近 12 周提交，高度 `16 + ((seed * (i + 3) * 7) % 84)` 百分比 —— 看起来像真数据，但完全由 uid 决定。
- **摘要与页脚**：`8 位贡献者 · 近 12 周 268 次提交`、最近一次贡献时间、这个空间累计被访问次数。

### 发布页：仿 GitHub 新建仓库

`#/publish` 的表单结构照着 GitHub 的 new repository 走：所有者 + 仓库名合成包名（`#pub-owner` 下拉 + `#pub-name` 输入，视觉上连成一行）、下面紧跟一句实时校验（`包名可用：dsh-demo-plugin · 装好后命令是 pnpm dsh add dsh-demo-plugin`，不合法时改红字说明原因）、再往下是描述、可见性单选卡、分类 chips、许可证下拉、拖拽上传区、四条发布前确认。

三个实现细节：

- **输入不重绘**：`#pub-name` 的 `input` 处理器只改 `#pub-name-tip` 的 innerHTML、右侧预览卡的包名、提交键的 `disabled` —— **不调 `render()`**。整页重绘会把正在输入的光标位置、滚动位置一起丢掉。
- **提交键三态**：包名合法 + 四条勾满 + 有安装包，三者齐了才 `disabled=false`；`.pub-hint` 同步显示还差哪几样（`还差：安装包 / 发布条款`）。
- **拖拽是模拟的**：点一下上传区就当作读到了一个 `pkg-0.1.0.tgz`（1.2 MB，sha256 是演示值），但 package.json 解析、sha 计算、审核态流转的界面都是真的。

## 账号身份、主题、地区（v15）

> v15 原本是「八个账号随便切」，那套切号器已被 **v17 的单账号单会话**取代（见[下节](#登录注册与单会话v17)）：现在身份只从**登录状态**来，弹层里只剩「退出登录」。本节讲的是 v15 留下来的三件事 —— 身份要从一处取、深浅与深海分开、地区跟账号走 —— 这些在 v17 里依然成立。

### 账号是真账号，不是「一个人到处发帖」

早期版本全站只有一张脸：发日志、评论、回复、发帖、发插件一律署名 `u1`，换个页面看别人空间，切回来还是自己。v15 把「当前登录的是谁」抽成状态位：

- `S.account`（默认 `'u1'`）是当前账号；`ME()` 返回它，全站 28 处硬编码的 `av('u1', …)` 与四处 `user: 'u1'` 全部换成 `ME()`。
- 资料 / 头像 / 封面**按账号存**：`S.accounts[uid] = { profile, avatar, cover }`，`acct(uid)` 按需建槽（不传 uid 就用当前账号），`meAva()` / `meCover()` 是「我的头像/封面」两个出口。`profileOf(uid)`、`avaOf(uid)` 都接受 uid 参数，不传才取当前账号。
- 顶栏头像点开的弹层里原本有一格「切换账号」（`.acc-btn` 八格）。**v17 已整个删除** —— 切号等于绕过登录规则，现在换成 `AUTH.state()` 那份会话态：登录 / 注册 / 退出 / 被拒都在 `#/login` 与弹层里收口。
- 发言署名跟着走：新日志、评论、楼层回复、社群发帖、发布插件全部记在 `ME()` 名下，头像、昵称、等级、城市都从 `profileOf(ME())` 取。

### 主题只管深浅，深海底色跟着路由

「在 `#/space/u1` 深色模式浅色模式混乱」的根因是两套东西混在一个开关里：`html[data-theme]` 是**全站深浅**，`.wrap.deep` 是**深海版块外观**。v8 阶段深海版块在白天主题下也是深底，于是「白天点了空间页还是黑的」看着像主题失灵。

v15 把深海也做成双主题：`.wrap.deep` 的默认值就是**浅海**（`--sea-bg` 是浅蓝到青白的三层径向渐变 + 一条 `#eaf7ff → #c9e3f6` 的线性渐变），`html[data-theme="night"] .wrap.deep` 才切回原来的深海取值。于是：

- 白天 + 空间页 = 浅海，夜里 + 空间页 = 深海，四个组合都成立；
- 深海版块的变量域没变，`:root` 的 `--brand` / `--brand-ink` 一个都没动，动效与对比度断言不受影响；
- 深海装饰层（光束 / 暗流 / 气泡 / 鲸尾）在浅海底色下重算了颜色（`--sea-ray-bg`、`--sea-bub-bg`、`--sea-fish` 等），从「白色高光」改成「淡蓝暗面」，不会在浅底上糊成一片白。

### 地区跟账号绑定

地区原先写死在 `profileOf()` 的兜底值里（浙江 / 杭州），谁看都是同一个地方。现在：

- `users` 表本来就只存城市（`city`），新增 `provOfCity(city)` 从 `profileOptions.provinces/cities` 反查省份，保证每个账号一进资料卡就带完整「省 市」；
- `profileOf(uid)` 的两级兜底是 `profile.province || provOfCity(users[uid].city)`，城市取 `profile.city || users[uid].city`，不再有全站统一默认值；
- 编辑资料页改的省市写进 `S.accounts[当前账号].profile`，切到别的账号看不到；
- 页面**不读**浏览器地区：全站 `timeZone` / `Intl` / `geolocation` / `navigator.language` 零命中，地区只有一个来源 —— 账号资料。

## 标题层级、分类真源、发帖插图（v16）

这三处原来是三个独立的坑，根子都是**同一个信息被写了多份**。

### 主副标题：一处刻度，两处同源

问题是三处各写各的字号：列表行 `.th-title` 14px、详情页 `.post-head h1` 19px（而且同一条 CSS 在 `css/app.css` 里写了**两遍**，后面那遍把前面的覆盖掉）、编辑器字段又是另一套 12.5px 的 label 规则。副标题更乱：列表把它当独立灰小字（`.th-ex` 12px），详情页却把摘要和正文**粘进同一个 `.tb-text`**——详情页根本没有「副标题」这个元素。

改法：

- `:root` 里立了七个排版刻度 `--fs-title-list / --fs-title-detail / --fs-sub-list / --fs-sub-detail / --fs-body / --fs-label / --lh-title`，比例写死在注释里（详情 = 列表 ×1.36，副标题 = 标题 ×0.86 且转 `--txt-2`），**别处不许再写死 font-size**。
- 删掉重复定义的 `.post-head h1,.post-head h2`，把 `.tb-text` 的三个字号（14 / 13.5 / 媒体查询）统一收到 `var(--fs-body)`。
- 数据侧给 `threads` 加了 `sub` 字段（八条演示帖都补了），详情页新增 `.tb-sub` 段落、正文从 `.tb-text` 里剥离出来。列表 `.th-ex` 与详情 `.tb-sub` **读同一个 `t.sub`**，同一句话在两页长得一样。
- 社群发帖表单补了 `#nt-sub`（选填，maxlength 80）。留空时 `ntsubmit` 取正文首句（按 `。！？!?
` 切）当 `sub`，同时写进 `excerpt` —— 老数据没有 `sub` 的走 `t.sub || t.excerpt` 兜底。

### 分类：只剩一份真源

原先至少有四份分类常量各自为政：`railHTML()` 里一个局部 `const CATS` 遮蔽了模块级的、`marketPage()` 一个、`publishPage()` 一个、`data.js` 的 `categories` 一个。而「分类重复」在界面上其实有两个来源：

1. **文案不一致**：首页左栏第一行叫「全部话题」，社群页叫「全部」——同一件事两个名字。
2. **双维度撞车**：帖子既有 `cat`（十三个分类）又有 `tag`（主标签），行内两个徽章都画。原来靠 `c.name === t.tag` 去重，这个字符串相等**只在「公告」这一条上恰好成立**，「经验分享」永远不等于「经验」，于是五分之四的帖子都在同一行重复表达同一个维度。

改法：

- 插件分类抽到 `data.js` 的 `pluginCats`，三处调用点都改成 `['全部'].concat(pluginCats)` 或 `pluginCats.slice()`；分类真源只剩 `categories` 与 `pluginCats` 两个数组。
- 新增 **`catTagAlias` 同义映射表**（`{ notice:'公告', guide:'经验', help:'求助' }`），去重判据从字符串相等改成 `catDupOf(t)`，列表行与详情页共用同一个函数。
- 计数统一走 `threadCountOf(id)` / `tagCountOf(tag)`，池子是 `threadPool() = S.newThreads.concat(threads)` —— 之前计数只数静态 `threads`、列表却含 `S.newThreads`，发完帖会出现「显示 8 个话题、列表 9 行」。
- 点分类时**无条件清掉 `S.ftag`**：分类与标签是两套维度但同时只有一个在生效，否则会得到「分类条数字变了、列表还是空的」这种自相矛盾的画面。
- 分类表从 6 类扩到 **13 类**（`js/data.js:277` `categories`，公告 / 技术开发 / 工具部署 / 国产软件 / 经验分享 / 求助问答 / 资源分享 / 网盘资源 / 优惠福利 / 科技快讯 / 网络考古 / 灌水闲聊 / 站务反馈）。名字按本站语境重写过：`dev` 从「插件开发」改成「技术开发」（写插件只是其中一块），`tool` 从「工具与部署」改成「工具部署」（176px 的栏里中间那个「与」只会换行）。**加分类只改两处**：`categories` 加一条，再给 `fcatCardHTML()` 里的配色表 `G`（`js/app.js:959`）补一行渐变 —— 漏了不报错，但会回落到灰色底，一眼能看出没配。
- 演示话题相应补到 14 条（新增 `t9–t14` 覆盖 cn / res / pan / news / chat / ops 六个新分类），**优惠福利与网络考古故意留 0** —— 新开的板块本来就该是空的，填满反而假。计数串因此固定为 `14,2,1,1,1,2,2,1,1,0,1,0,1,1`，写死在前端与自检脚本的期望值里，再动分类要一起改（断言失败时会把实际串打出来，直接抄）。

### 发帖插图：链路断了三处

根因不是上传接口，而是**前端根本没发起上传**：

- 发日志框与回帖框的工具条按钮是纯 `<button class="tool">`，**没有 `data-act`**，点了什么也不发生，只有 `:hover` 样式在造「可点」的假象；
- 没有 `<input type="file">`、没有 `paste` 监听、没有 `drop` 监听；
- `publish` 里读的 `S.pendingImages` **全仓没有写入点**，本地降级分支的 `images` 硬编码 `[]`。

现在的链路（日志框与社群发帖各一套队列，`pendingImages` / `ntImages`，只在内存不落盘）：

```
选文件 / 粘贴 / 拖入 ─→ addImages(files, queue) ─→ 校验（类型白名单 4 种、单张 ≤5 MB、最多 4 张）
                     └─→ readImage(file) ─→ FileReader → dataURL + naturalWidth/Height
                          └─→ repaintImgs(queue, prevId) ─→ 只换 #imgprev 节点与计数徽标（不整页重绘，草稿和焦点都保住）
```

发表时 `Promise.all(imgs.map(API.uploadImage))` 把 dataURL 换成 `{key,w,h,type,url}` 再交给 `API.publish`；后端 401 提示先登录，5xx 或断网时降级成「已先存进本地演示流」（本地演示流直接用 dataURL 渲染，所以离线也能看到图）。灯箱也扩了真图通道（`.stage.has-img` + `.lb-img`），主楼配图与日志配图都能点开。

**踩到的两个真 bug**（都已修，记在这里免得复发）：

1. `change` 监听里先 `e.target.value = ''` 再读 `e.target.files` —— `FileList` 是**活引用**，清空之后读到的永远是空列表，于是「选了图却入队 0 张」。改成先 `Array.prototype.slice.call(files)` 拷成真数组。

## 登录、注册与单会话（v17）

### 三条硬规则

| 规则 | 落点 | 违反时的用户可见结果 |
| --- | --- | --- |
| **必须先注册才能登录** | `AUTH.login()` 里先查 `DB.accounts[email]`，**查不到直接抛 `NOT_REGISTERED`，密码校验都在它之后** | 表单下红框「这个邮箱还没注册，先去注册一个账号」+ 一个「去注册」按钮，并把邮箱留在注册 tab 里（不用重填） |
| **同一账号在同类设备上只有一条会话**（v46） | `sessions` 表按 `(user_id, device)` 分组，`device` 只有 `pc` / `mobile` 两个字面量（由 UA 推） | 同一类设备重复登录被拒：`ALREADY_ONLINE`「这个账号在这台设备上已经登录了，同一设备同一时间只保留一条会话（手机和电脑可以同时在线）」，登录框给「顶掉电脑 / 手机上的登录」 |
| **登录状态建立后不能在本会话换号** | `AUTH.switchTo()` 恒抛 `AUTH_LOCKED`；界面上切号器（`.acc-btn` 八格）已整个删除 | 弹层里只有「退出登录」（⏻ + 副文案「退出后才能换个账号登录」）；万一有残留入口点了会 toast「已登录状态下不能切换账户，请先退出登录」 |

**为什么绕不过去**：会话不是「页面上写了个已登录的变量」，而是 `localStorage['jy-auth-v1']` 里的一条 `sessions[uid]`（含 `sid`、签发时间、UA、手机号态）加一条 `device`（本浏览器认哪条会话），再加一份 `sig` —— `sigOf({sid, uid, email})` 的校验和。`current()` 每次读身份都做五重校验（设备存在 / 该账号的会话 sid 与设备一致 / 未过期 7 天 / 签名对得上 / 账号 uid 对得上），任一失败就 `clearDevice()` 回访客态。手改 localStorage 里 `device.uid` 会因为 sid 与账号对不上被清；手改 `sessions` 会因签名不对被清。所以「改个字段就变成别人」这条路是死的。

> 承认边界：这是**纯前端演示**，密钥写在前端（`SECRET='jingyu-demo-2026'`），能挡住「随手改 localStorage」，挡不住「读源码重算签名」。真正的强约束在后端（`server/src/auth.js` 用 `sessions` 表 + JWT + 单用户唯一索引），前端这套只是把同样的语义先跑通给用户看。

> **换片策略（v26：一段演完自动换下一段）**
>
> 三个落点（首页头图、鲸鲸空间头图、登录页左卡）加载的是同一个 `whale/index.html`，卡里改一次，三处同时生效。
>
> - `switchTo()` 里 `next.loop = false`：一段只演一遍，不再无限循环。片段都是待机呼吸 / 点击回应 / 节日小剧这类循环素材，无限循环看起来像「人僵在那里」，播完停在最后一帧更明显。
> - `ended` 一到就 `playRandom()` → `randomClipExcept(cur)`：在除刚演完那段以外的 106 段里等概率抽，不会连着放同一条。`vids` 里另一路（淡出中的旧层、预取层）的 `ended` 用 `dataset.clip !== cur` 挡掉。
> - 双击 / 回车仍然随时可打断，打断之后照样按「新这段演完再换」继续 —— 换片权从「只有用户」变成「用户 + ended」。
> - `syncViewState()`：卡片滚出视口或标签页切后台就暂停。iframe 自己的 viewport 永远「看得见自己」，所以要用 `window.frameElement.getBoundingClientRect()` 和父窗口的 `innerHeight/innerWidth` 求交；父窗口 `scroll`/`resize` 与 `visibilitychange` 都挂了这个函数。回来先续播；若 `ended` 发生在后台，`pendingAdvance` 记一笔，回到屏内立刻换。60MB 素材连播一小时是几百 MB，看不见时不能空跑。
> - 失败兜底：`play()` 被策略拒绝、`error`、或某个片段压根等不到 `ended`，连续三次就 `setStatic('片段连续加载失败')` 退回静态立绘，不会永久停在最后一帧。
> - `window.__whale.state()` 里 `loop` 现在是 `false`，另加了 `paused`（当前是否被视口/后台按住）。
>
> ⚠ 改了 `whale/index.html` 的内联脚本，线上 CSP 白名单里的 sha256 就得跟着换（见本文件「CSP」一节）；`bash deploy/deploy.sh` 会先对账并 `warn` 出新值。

### 四、拖拽边界怎么算

`measureBounds()` 里分两支，bare 走这套：

```js
var side = Math.round(w * 0.22);                    // 视频画面左右各带一段透明留白
var span = Math.max(0, Math.round((card.clientWidth - w) / 2));
BOUND.left  = span + side;                           // 抵到卡左缘时可见的本体刚好贴边
BOUND.right = span + side;                           // v25：与 left 对称，右缘同样吃掉留白
BOUND.up    = Math.round(top + h * 0.139 - 1);       // 0.139 = 本体顶端在画面高度上的位置
```

`0.139` 是拿真片段画进 canvas、逐像素扫 alpha 量出来的（640×360 里 bbox y=50..330）；沿用旧的 16% 会**把脑袋切掉 7px**。默认站位 `HOME.x = Math.max(0, BOUND.right - 56)`（右边缘距卡边 56px），首帧就站在右边，不从中心滑过去，同时留出往右拖的余量。

> **v25 修掉的 bug**：`BOUND.right` 原本是 `Math.round(span * 0.32) + side` —— 732×208 的首页卡上算出 134，比默认站位（`span - 18` = 228）还小，`clampPos()` 一上来就把人钳在 134，**往右一格都拖不动**，左右边界也根本不对称（左 284 / 右 134）。

### 四之二、拖拽 = 基准 + 指针位移（v25）

v24 的 `pointermove` 把**相对按点的位移**当成**绝对位置**写进 `pos`：`pos.x = clamp(p.x - drag.sx)`。角色从默认站位（228）一按一移就跳到指针位移处（≈0）—— 这就是「鼠标交互的瞬间人物会瞬移」。实测：按下 228 → 移 4px → 变 4（差 −224）。

v25 改成按下记基准、移动只加增量：

```js
pointerdown:  drag.bx = pos.x; drag.by = pos.y;
pointermove:  drag.pdx = p.x - drag.sx; drag.pdy = p.y - drag.sy;
              if (dragging && !rafDrag) rafDrag = requestAnimationFrame(flushDrag);
flushDrag():  pos.x = clamp(drag.bx + drag.pdx);
              pos.y = clamp(drag.by + drag.pdy);
```

| 改动 | 为什么 |
| --- | --- |
| 拖拽阈值 5px → **3px** | 更跟手，又不至于把单击误判成拖拽 |
| 位移合并进 `requestAnimationFrame` | 高刷鼠标一帧派发 2~8 个 `pointermove`，每个都写 `--dx/--dy` + `--tiltX/--tiltY` 会触发多轮样式重算 |
| `endDrag()` 先 `cancelAnimationFrame` 再补一次 `flushDrag()` | 否则排队中的最后一帧被取消，松手前那一小段位移丢失（表现为「松手回跳几像素」） |
| 拖拽中跳过 `--mx/--my` 悬停写入 | 下一帧就被 `flushDrag` 覆盖，白跑一轮重算 |
| `physics()` 收敛目标 原点 → `HOME`（`k=0.02, c=0.22`，阈值 0.2px） | 原来目标是 `(0,0)`，bare 下 `HOME.x≈228` 永远到不了 0 → `raf2` 空闲也在每帧跑，且松手后角色被拽回卡片正中，与「拖到哪停在哪」矛盾 |
| `clampPos()` 末尾把 `HOME` 也钳进边界 | 窗口 resize 后不会被吸到界外 |
| `.dock{will-change:transform}` + `.card.dragging .char{transition:opacity .16s linear, filter .3s ease}` | 掐掉 `.char` 原本 .35s 的 transform 过渡，否则与指针位移叠加成拖尾 |

### 六、七个真坑

1. **关键帧把角色的拖拽位移吃掉了**。`.card.poke .dock{animation:squash}` / `.card.dizzy .dock{animation:wobble}` 的关键帧只写了 `translateX(-50%)` —— animation 会覆盖整条 `transform`，于是摸摸、甩出去的那一刻 `--dx/--dy` 全部失效，角色瞬移回卡片中心再弹回来。v23 位移只有 ±110px 不明显，v24 能横跨整张卡、默认还站右侧，一拖到最左就露馅（截图里人贴在左边、下一帧跳到中间）。修法：关键帧里补 `translate(var(--dx,0px),var(--dy,0px))`，且放在 `scale/rotate` 之前。
2. **`#/art` 首屏偶尔整卡变静态**。`initVideo()` 用 `hasAlpha()` 探测透明通道，探测片段原来是 `randomClip()` —— 池子里 `c001 被落叶淹没_HD.webm` 是 3840×2160 纯黑底、没有 alpha，抽到它就判成「当前浏览器不支持透明视频」。修法是 `randomAlphaClip()`，开屏探测与热身只从带 alpha 的片段里抽。**2026-10-24 已把这两段「被落叶淹没」（HD 与标清）整体移出随机库**，池子从 107 段降到 105 段、全部带 alpha，这条坑因此消失；`randomAlphaClip()` 与 `a:0`/`.noalpha` 那套兜底照旧留着，将来再塞黑底素材时不会重蹈。
3. **测量几何要等 1.2 秒**。甩出去（松手速度 >900）会挂 `.dizzy` 摇摆 1.2s，9° 旋转会把 `getBoundingClientRect` 的 top 抬高近 60px —— 自检里立刻量「头顶是否抵到卡顶」会假失败，必须等摇摆结束。
4. **CDP 的 `clip` 是文档坐标，不是视口坐标**。`clipShot()` 原来直接用 `getBoundingClientRect()`（视口坐标）当 clip —— 页面滚过之后就截出一张空图（`_v24-hero-feed-d.png` 只有 2.6KB、整张浅灰就是这么来的），而且它不报错。修法：先 `window.scrollTo(0,0)`，再把 `scrollX/scrollY` 补进 rect，并带上 `captureBeyondViewport:true`。
5. **只改 hash 的 `Page.navigate` 不会重建文档**。出图前为了「回到初始状态」再 navigate 一次同 URL 是没用的 —— 上一节拖到左边的角色会原样留在那儿被拍进图（`_v24-hero-feed-d.png` 里角色偏左就是这个原因，而几何断言全绿，因为它自己重新 navigate 过）。修法：出图走 `index.html?bust=N#/route` 真重载。
6. **右边界比默认站位还小，等于「往右拖不动」**（v25）。`BOUND.right = Math.round(span * 0.32) + side` 在 732×208 上算出 134，默认站位却是 228 —— 站位天生在界外，`clampPos()` 一上来就钳到 134。症状是「往右一格都推不动、往左却能动 150px」，很像 CSS 或指针事件的问题，实际是一行算错的边界。判据：`__whale.state().dx` 与 `bound.right` 相等且 `bound.right < HOME.x`。修法：`BOUND.right = span + side`（与 left 对称），默认站位改 `BOUND.right - 56`。
7. **相对位移当绝对位置写**（v25）。`pos.x = clamp(p.x - drag.sx)` 会让角色在按下瞬间从 228 跳到 ≈0 —— 看上去像「瞬移」或「点一下就跑到鼠标下」。正确写法是按下记 `drag.bx = pos.x`，移动时 `pos.x = clamp(drag.bx + (p.x - drag.sx))`。

### 八、改卡片的注意

`whale/index.html` 就是站点里 iframe 加载的那一份，仓库里只有这一份副本，改完不需要再同步别处。

更阴的一步：`whale/index.html` 里有**两段内联 `<script>`**，nginx 的 CSP 用 sha256 白名单放行，动了其中任何字符（**哪怕只是改一句注释**）哈希就失效。改完必须重算这两段的 sha256：`node deploy/build.mjs` 会把每条内联脚本的哈希写进 `dist/csp-hashes.json`，照着替换 `/etc/nginx/snippets/security-headers.conf` 里那串 `sha256-…=`（改前先 `sudo cp -a` 备份一份 snippet），最后 `sudo nginx -t && sudo systemctl reload nginx`。
漏了的表现是「鲸鱼娘整块不加载 / 主题闪白，控制台报 CSP 拦截」—— 看着像玄学，其实是哈希没跟上。

**静态 Q 版立绘已从素材库移除**（2026-10-25）：`whale/assets/pose-front.webp` 与 `pose-mature.webp` 已移到仓库外的 `tmp/removed-whale-static-20261025/`（可回滚），`whale/index.html` 里不再有 `STATIC_PICS` / `addStaticPics()` / `.char.pic` / `data-mode`。`initVideo()` 判定降低动效 / 省流量 / 浏览器不支持透明视频 / 片段加载超时（4s）时，`setStatic()` 现在只把状态行改成「动态立绘不可用 · 原因」，**不注入任何静态图**；双击也不会再切成熟形态。`measureBounds()` 只量 `video.char`（opacity 不影响 offsetWidth/Height）。要恢复旧降级图，从备份目录搬回 `whale/assets/`，再按上一段重算 CSP 哈希。

## 空间封面：本地上传 + 保存后落回空间（v28）

编辑资料页的「空间封面」原来只有 6 张预设渐变，用户自己的图进不来；「保存资料」又停在表单里不动 —— 改完的资料（尤其那张刚换上去的封面）得自己再找一次入口才看得见。这一版（下文按 v28 记）补上这两头：**封面支持本地图片**，**保存即回到自己的空间**。

### 一个字段，两种值

封面从来没进过服务端模型：它就是 `S.accounts[uid].cover` 里的一条 **CSS background 简写**（兜底是空串，表示跟主题走；见 `js/app.js:328-343`）。预设存 `linear-gradient(…)`，上传存 `url(data:image/jpeg;base64,…) center/cover no-repeat` —— 两种值都能原样塞进 `style="background:…"`，所以三处渲染（首页名片 `js/app.js:2134`、编辑页预览 `js/app.js:3877`、空间头图 `js/app.js:3965`）一行都不用改。新增的 `coverIsImg(c)`（`/^url\(/i`）只回答「这张是不是用户传的图」，预设格的选中态与上传格互斥全靠它。

### 为什么只缩不裁

头像裁成方形天经地义，封面不行：同一个 cover 要在 **200px 高的空间头图 / 74px 高的首页名片 / 78px 高的编辑页预览** 三种比例里显示，`background-size:cover` 每次各裁一份。上传阶段先裁成 2:1，竖图两侧的内容就永久没了。

> v33 起这一步不再由代码替用户决定：图先过裁切器，**用户自己框**（见「空间封面：上传后自己取景」一节）。「只缩不裁」的原则没变 —— 变的是「哪一块算封面」这件事交回了用户手上，框内的内容不会再被压一次。

| 环节 | 取值 | 理由 |
| --- | --- | --- |
| 类型白名单 | png / jpeg / webp | 和头像同一套 `COVER_TYPES` |
| 原件上限 | 10 MB | 只是防呆；真正落盘的是压完的那份 |
| 缩放阶梯 | 1400@.82 → 1200@.78 → 1000@.74 → 860@.7 → 720@.66 | 只等比缩小；宽度不够就原尺寸重编码，不放大 |
| 落盘上限 | `COVER_MAX_CHARS = 900 KB`（dataURL 字符数） | localStorage 一共 5 MB，还要留给点赞 / 评论 / 作品图；`saveState()` 爆配额时先 strip 楼层图再 strip 主楼图，封面不该去挤那条通道 |
| 透明处理 | 压 JPEG 前先 `fillRect` 铺白 | 透明 PNG 直接 `toDataURL('image/jpeg')` 会把透明区压成**黑**块 |

实测：1600×600 的测试 PNG（原始 114 KB）→ 1400×525 JPEG q0.82 → dataURL **30,763 字符**，远在闸门之内。

### 坑

- **别拆成 `background-image` + `background-size` 两个属性**：`cover` 只有一个字符串槽，预设的 gradient 和上传的 url 要走同一条渲染路径，拆开就得在三个渲染点各写一遍分支。
- **文件框必须 `input.value = ''` 复位**（与 `ava-file` 同一个坑）：不复位则同一张图选第二次不触发 `change`。
- **压缩期间要禁点**：大图解码 + 逐级编码有几百毫秒，上传格先改成「正在压缩封面…」并 `disabled`，否则用户以为没反应，连点两下又开一次文件框。
- **头像与封面两套处理逻辑刻意分开**（`handleAvatarFile` / `encodeCover`）：前者居中切方、后者按用户框出的矩形取景，别为了省代码合并成一条 —— 裁切策略是相反的。

## 空间封面：上传后自己取景（v33）

v28 把本地图接了进来，但存下来的是「整张图等比缩一次，然后三处各自 `cover` 裁」：同一张宽幅照片，进 3.63:1 的空间头图切一次、进 1.8:1 的手机头图又切一次、进 ≈4:1 的首页名片再切一次。人像常常只剩半张脸，而界面上没有任何地方能说「我要的是这一块」。v33 在上传与压缩之间插一步取景：图先进裁切器，**用户框住要露出的那一段**，存下来的就是那一段。

### 为什么框是 3:1

实测三处真实宽高比（`getBoundingClientRect`，1280 / 390 两档视口）：

| 落点 | 尺寸 | 比例 |
| --- | --- | --- |
| 空间头图 `.prof-cover`（1280） | 726 × 200（`.layer` 724 × 198） | 3.63 |
| 空间头图（390 手机） | 354 × 200 | 1.77 |
| 首页名片 `.me-card .banner` | 随列宽 / 高 74px | ≈4.0 |
| 编辑页预览 `.prev-cover` | 随列宽 / 高 78px | ≈4.0 |

3:1 是这几个数的折中：桌面头图上下各切约 17%，手机左右各切约 40%。往手机那边对齐（1.8:1），桌面会把四成高度切掉；往名片那边对齐（4:1），手机上只剩一条缝。要改就改一个常量 `CROP_RATIO`，验收表里的实测数字跟着一起改。

### 交互

| 动作 | 行为 |
| --- | --- |
| 拖框内 | 平移取景框，边界钳在图片内（`setPointerCapture`，指针移出窗口也不丢） |
| 拖滑杆 / 键盘调滑杆 | 以**框中心为锚**把框等比放大缩小，30%–100%；最小宽度另受屏幕像素约束（`72 / sc`），缩到再小就没法用手指拖了 |
| 点框外、图内 | 框以点击点为中心跳过去（再钳位）；点框内不动 —— 那里是拖动的起点 |
| 方向键（框聚焦时） | 6px 微调，`Shift` + 方向键 24px |
| Esc / 取消 | 关掉，封面一个字不改 |
| 使用这张 | 按框出的矩形出图 → 写入 `acct().cover` → 关弹层 → 重绘 → toast |

初始框 = 能塞下的最大 3:1 区域并居中（`min(iw, ih*3) * 0.999`）。所以「传上来什么都不动就点确认」等于 v28 的行为，不会因为多了这一步反而变差；框等于整图时 toast 说「封面已换成这张图」，否则说「封面已换成裁好的这一段」。

### 为什么是命令式弹层，而不是又一个 render 分支

裁切器是挂在 `body` 上的 `.cropper`（`openCoverCrop` 里拼 innerHTML、`closeCoverCrop` 里摘掉），**不进 `S`、不走 `render`**：

- 拖动时每帧重绘整页会掉帧，而且 `setPointerCapture` 的捕获对象会被 innerHTML 换掉，手指一移就断。
- 弹层也在 `.wrap` 之外，顺手绕开 `.wrap.deep` 作用域：深海主题的 token 只挂在 `.wrap` 子树上，弹层配色写死深底，昼夜两套主题下都读得清 —— 不用再写一份 `.wrap.deep .crop-*` 变体。
- `cropState` 只在弹层活着时存在，**绝不塞进 `S`**：`S` 会被 `saveState()` 序列化，里面放一个 `HTMLImageElement` 进去，整份存档就写不成功了。
- 框外压暗用一个 `.crop-frame` 的 `box-shadow: 0 0 0 9999px rgba(4,10,18,.68)`，比四个遮罩 div 少一半节点，而且拖动时只有一个元素要重排。

### 编码：只缩不裁，其他照旧

`encodeCover(im, sx, sy, sw, sh)` 取代了 v28 的 `shrinkCover(im)`（按整图出图就是 `0,0,iw,ih`，那次调用点已无残留）：

- 只**等比缩小**，不放大：`k = min(1, 1400/sw)`，竖图或小图原尺寸重编码。
- 压 JPEG 前先 `fillStyle='#fff'` 铺白 —— 透明 PNG 直接 `toDataURL('image/jpeg')` 会把透明区压成黑块。
- 阶梯仍是 `[[1400,.82],[1200,.78],[1000,.74],[860,.7],[720,.66]]`，闸门 `COVER_MAX_CHARS = 900 KB`，落盘值仍是那条 `url(data:…) center/cover no-repeat`。

### 无障碍

`role="dialog"` + `aria-modal="true"`；打开时锁 `body` 滚动、焦点给取景框（`tabindex="0"`、`role="application"`、`aria-label="取景框，方向键微调"`）；`keydown` 挂在 `document` 捕获阶段：`Esc` 直接关（`stopPropagation`，不让它顺带触发页面的关闭逻辑），`Tab` 只在弹层内的 `button / input / [tabindex]` 之间循环。关闭后焦点回到打开它的上传格。

### 响应式

- ≤560px：滑杆独占一行，`取消 / 使用这张` 一起落到第二行、右对齐。早先让它们和滑杆抢同一行时，「取消」会粘在滑杆尾巴上、和下一行的「使用这张」拆成两半，看着像两个不相干的操作。
- 视口高 ≤560px（手机横屏）：隐藏说明文字、图压到 `34vh`。不这么做的话整张卡高过视口，取景框上下边会被 `.crop-stage` 的 `overflow: hidden` 切掉 —— 框不全，用户根本没法判断自己框到了哪。卡片本身仍是 `overflow: auto`，极端情况下能滚。

### 坑

- **`cropState` 不能进 `S`**（见上）。同理，弹层里的 `img` 元素只能从 `cropState` 拿，别写进任何全局状态。
- **忙碌态要能收回**：`handleCoverFile` 解码完把上传格改成「正在解码图片…」并 `disabled`，取消或失败后必须 `clearBusy()` 把文案和可点态还原，否则那一格永远卡在「正在解码」。
- **框的最小尺寸要跟着缩放走**：`minW = max(maxW*0.3, min(maxW, 72/sc))`，只算百分比的话，一张 6000px 宽的原图缩到 300px 显示时框会小到抓不住。

## 私信：会话列表 + 一对一聊天

站内一对一私信，接在现有账号体系上：仍是纯前端演示站，会话与消息存在本机 localStorage 的 `S.dm` 里，按**登录账号**分桶（`S.dm[ME()]`）——换号看不到别人的会话。（代码注释与样式段标的是 `v33 · 私信`；同期的「空间封面：上传后自己取景」也占了 v33，两件事互不相干。）

### 路由与入口

- 路由：`#/dm` 是会话列表，`#/dm/:uid` 直接打开某个人的会话；`pageHTML` / `hashOf` / `applyHash` 各一行（搜 `S.route === 'dm'`、`'#/dm'`、`r === 'dm'`）。
- 访客闸门：`GATE_LABEL.dm`，不在 `PUBLIC_ROUTES` 里 —— 没登录进 `#/dm` 会落 `#/login`，提示「请先登录：私信需要用账号身份进入」。注意只有**整页重载**才算数，登出后只改 hash 仍是登录内存态。
- 四处入口：
  1. 头像弹层「✉ 我的私信」，右侧挂总未读数；
  2. 消息中心页签右侧的「✉ 私信 N」胶囊；
  3. 消息中心里 `kind === 'dm'` 的通知行，按钮文案改「回私信」，点了直接进对应会话；
  4. 别人空间头图下方那颗 ✉（`aria-label="给 昵称 发私信"`）。

### 数据模型与未读口径

`S.dm[me][uid] = [{ id, from, text, at, read }]`，`from` 是 `'me'` 或对方 uid。没有服务端表：首次访问由 `dmSeed()` 给 u5 / u3 / u2 各播 2–3 条（含未读、时间戳错开成今天 / 昨天 / 前天），`dmBox()` 惰性建桶；规则升级时再加一条 u7 小满（未关注我的陌生人），用 `S.dmVer < 2` 兜住老存档、只补一次。

- 未读 = `read === false` 且 `from !== 'me'`，由 `dmUnreadOf(uid)` / `dmUnreadTotal()` 读。总角标（头像弹层 + 铃铛）里**排除陌生人会话与拉黑会话**：陌生人私信只在自己那一栏提示，跟 B 站一样不往总未读里堆。
- `dmMarkRead(uid)` 打开会话时把对方消息置读，**同时**把 `S.notices` 里 `kind === 'dm' && from === uid` 的通知 id 塞进 `S.noticeRead` —— 消息中心的私信通知和这里的未读是同一件事，不能一处清一处留。
- 列表按最后一条 `at` 倒序；行上时间今天显示 `HH:MM`、昨天 `昨天 HH:MM`、更早 `M/D`；聊天记录里按天插分隔条（今天 / 昨天 / M 月 D 日 / YYYY 年…）。

### 交互细节

- **Enter 发送、Shift+Enter 换行**：`keydown` 里判 `e.target.id === 'dm-input' && !e.shiftKey && !e.isComposing` —— 中文输入法选词时敲回车不会误发。正文按纯文本转义后换行转 `<br>`，不解析 HTML。
- 上限 **500 字**（`DM_MAX`，2026-10 按 B 站口径收紧，原来 1000），右下 `#dm-count` 显示 `n / 500`，`maxlength` 兜底；改过 `maxlength` 之后仍会走一遍 `dmSend` 的长度判断 —— 用 `HTMLTextAreaElement.prototype.value` 的 setter 塞进去的长字符串，`maxlength` 拦不住，只能靠这一道。textarea 跟着内容长高，120px 封顶。
- **草稿按人存**：`S.dmDraft[uid]`，切会话再回来还在；只放内存，刷新即弃（免得半句话被存档）。
- **会话搜索**：`S.dmQ` 匹配昵称与最后一条消息，只对已渲染的行切 `hidden` 并开关空态，**不重绘** —— 重绘会每敲一个字丢一次焦点。搜不到显示「没有匹配的会话」。
- ＋新私信：列出除自己外的 7 位联系人，已有会话的标「已有会话」，点一位就以 0 条消息开新会话。
- 桌面右栏头部那颗 `⋯` 菜单里第一项「🙋 TA 的空间」直接跳对方主页（v34 把它从头部挪进菜单，头部只留「已关注 / 关注」与 `⋯`）；≤760px 左侧出现返回键（`.dm-back`），返回先回列表、清空 `dmPeer`。
- **演示回复**：没有收件人，回复是本地定时器 `DM_AUTO`（每人一句固定台词，1.2s 后 push 一条对方消息）。会话开着就置读并重绘，不在当前会话则 toast「XX 回了一句私信」。定时器里先判 `ME() !== me`，换号后不会把回复写进新账号。

### 持久化，以及一个连带修掉的坑

`saveState` 把 `dm: S.dm` 一起写进 `dsh-forum-state-v1`，恢复在 `restoreState` 里。

这一轮顺手挖出一个**影响面比私信大得多**的旧坑：刷新后私信退回播种状态、留言板与账号资料也不恢复，可 localStorage 里的数据是好的。问题不在写，在读 —— `restoreState` 的 IIFE 里调了 `sweepFavOrder()`，它依赖后面才用 `const` 声明的 `FAV_KINDS`，模块求值时还在 TDZ，一句 `ReferenceError: Cannot access 'FAV_KINDS' before initialization` 被外层 `try/catch` 静默吞掉，于是 `artComments` / `newFloors` / `rpDraft` / `msgs` / `dm` / `accounts` / `account` **一个都没恢复**。

修法两处：`restoreState` 里不再调用（换成一段注释说明为什么不能在这里调），改在 `favSet()` 定义之后、`FAV_KINDS` 已初始化处调用一次。验证脚本 `.shots/probe-dm-persist5.mjs`：发送后 `localStorage` 里 `u1:u5` 是 4 条，`Page.reload` 后仍是 4 条，连最后那条自动回复也在。

顺带修了 `js/app.js` 状态对象里 `avatarErr` 少个逗号导致的整站 `SyntaxError: Unexpected identifier 'authTab'`。

## 私信规则：仿 B 站那一套限制（未关注折叠 / 1 条额度 / 2 分钟撤回 / 拉黑与举报）

v33 的私信只是个通用 IM：谁都能给谁发、想发几条发几条、发错也收不回。这一轮把「陌生人能不能发、能发几条、发出去能不能收回」补上，规则照 B 站私信那一套。状态全在前端（代码注释与样式段标 `v34`；验收脚本叫 `.shots/snap-lead-v35.mjs`，因为 README 里 `v35` 已被「我的收藏不再挂左栏」占用）。

### 关系：谁关注谁

- `DM_FOLLOW_ME = { u5: 1, u3: 1, u2: 1, u4: 1 }` 是写死的「谁关注我」；`S.dmFollow`（`Set`）是「我关注了谁」，聊天头部那颗按钮可切，落盘时转成数组。
- `dmRelation(uid)` 输出四种：互相关注 / 关注了你 / 你关注了 TA / 未关注你，显示在昵称后面（`Lv.x · 徽章 · 城市 · 互相关注`）。关注关系直接决定「陌生人额度」存不存在。

### 未关注人私信

- 判定 `dmIsStranger(uid)`：没被接收（`meta.accepted`）、对方没关注我、我也还没发过 —— 三条同时成立才算。
- **折叠**：列表把它拆进 `.dm-str` 虚线区，默认收起，头部「未关注人私信 N ▸」（`aria-expanded`，三角用 `.dm-str-ar` 转 90°，不换字符、宽度不跳），点一下写 `S.dmStrOpen`。有搜索词、或者正开着某个陌生人的会话时**强制展开**：否则命中的会话被父级 `hidden` 挡住，计数说「有结果」、列表却是空的；正在聊的那个人也会从自己的列表里「消失」，看着像没点中。
- **1 条额度**：`dmStrangerLeft(uid)` 数的是「最后一条对方消息之后我发过几条」，发过 1 条就归 0；`dmCanSend()` 是唯一出口（拉黑、额度、空串都在这里拦），额度用完时输入框直接 `disabled`、placeholder 换「等 TA 回复后才能继续发…」、发送键同灰。
- 对方一回复（`DM_AUTO` 的自动回复也算），额度恢复、会话自动移回正常列表 —— B 站是「对方回复后可以继续发」，不是「陌生人永久只能 1 条」。
- 顶部 `📮 未关注人私信` 横幅按「对方没关注我且我没接收会话」判，**不按「我发过没」判**：发过之后 `dmIsStranger` 变 false，横幅要是跟着消失，输入框被禁用就变成没来由的事。横幅上的「接收会话」写 `meta.accepted`，等于主动放行，之后不再限条数。

### 2 分钟撤回

- 自己的消息在 2 分钟内挂 `.dm-recall`（`DM_RECALL = 2 * 60 * 1000`），默认不显示，悬停或键盘聚焦才露出来 —— 每条消息底下都挂一条「撤回」太吵。
- `dmRecall(mid)` 只打 `revoked` 标记并清正文，渲染成居中的 `.dm-sys`「你 / TA 撤回了一条消息」；过期点它 toast「超过 2 分钟，撤不回了」。
- 撤回**不删记录**：留一行痕迹，和 B 站一致。

### 免打扰 / 举报 / 拉黑 / 删除会话

- 聊天头部 `⋯`（`.dm-more`）开 `.dm-menu`，6 项：TA 的空间 / 关注·取消关注 / 免打扰 / 举报 / 拉黑 / 删除会话。事件委托里**每个 `data-act` 都要有处理器**：漏掉 `dmmenu` 时菜单根本点不开，后面所有断言跟着一起红。
- 免打扰写 `meta.muted`：列表行右侧挂 🔕，`dmAutoReply` 不再弹 toast（页面开着仍照常进消息）；再点一次取消。
- 举报开 `.dm-rep-mask` 弹层，4 个理由（垃圾广告 / 人身攻击·辱骂 / 色情低俗 / 诈骗·引导私下交易），选一个才能提交；提交只 toast —— 演示站没有版务后台。
- 拉黑写 `meta.blocked`：横幅换 `⛔ 已拉黑 TA`，输入区整块替成 `.dm-composer.is-off`，`dmAutoReply` 也不再起定时器；横幅里的「解除拉黑」恢复原状。

## 点头像进空间：全站头像变成入口（v40）

以前头像基本是「点了什么都不发生」的那一半：昵称能点、头像不能。v40 把**别人的**头像都变成入口 —— 点一下直接进他的空间，和点昵称走同一条路；自己的头像保持原样（导航那颗点了要开账号弹层，不能变成「跳回自己的空间」）。

### 哪颗头像能点

`av(uid, size, cls)` 只给别人的头像挂三样东西：

```html
<img class="av" data-avuid="u3" role="link" tabindex="0" aria-label="进入 豆腐 的空间">
```

自己的头像（`uid === S.account`）不加 `data-avuid`，所以导航头像、账号弹层、首页右栏名片、自己空间头图点下去还是原来的行为。

### 点击判定为什么必须排在 [data-act] 前面

全站点击委托的第一句是「找最近的 `[data-act]`」，而日志行、私信列表行、访客位置都是**整块可点**的容器。头像长在容器里，要是先拿到外层动作，在私信列表里点头像就会开聊天而不是进空间 —— 所以头像这一支插在 `const el = tgt.closest('[data-act]')` **之前**，命中就 `return`，不再往下走。

排除清单（这些地方的头像属于控件本身，点它应该完成控件的事）：

| 容器 | 点下去应该发生什么 |
| --- | --- |
| `.men-panel` | 提及面板：插入 `@昵称` |
| `.dm-newbox` / `.dm-contact` | ＋新私信：开这个人的聊天 |
| `.cn-cell` | 贡献者格子：外层已经是按钮，别再嵌一个可聚焦的图片 |
| `.nav` / `.pop` | 账号弹层相关 |
| `.dm-menu` / `.dm-rep` | 会话菜单、举报层 |
| `.lb` | 灯箱 |

同一个空间里再点自己的头像不做无谓重绘（否则会把你正在看的「相册 / 留言」标签重置回日志）。

### 键盘与视觉

- 键盘：Tab 能停在头像上，Enter / 空格等于点击；`:focus-visible` 给 2px 品牌色环（`outline-offset:2px`）。
- 指针：`cursor:pointer` + hover 提亮 6%；不加常驻描边 —— 头像本身大多自带边框 / 阴影，再描一圈会脏。`prefers-reduced-motion` 下关过渡。

## 插件页点赞胶囊（v41）

仓库页右上角原来是「收藏 + 复制安装命令」两颗胶囊。v41 在收藏左边补了一颗**点赞**：

```
[ 👍 点赞 1,648 ]  [ ☆ 收藏 2,841 ]  [ ⧉ 复制安装命令 ]
```

### 点赞与收藏不是一回事

| | 点赞 | 收藏 |
| --- | --- | --- |
| 语义 | 表个态，数字 +1 | 收进「我的收藏」，以后能找到 |
| 存在哪 | `S.likePlug`（本机 Set，落盘） | `S.favPlug`（同一份存档，收藏页会列出） |
| 数字从哪来 | `Math.round(stars × 0.58)` + 本机 1 | `stars` + 本机 1 |
| 会不会进收藏页 | 不会 | 会 |

点赞的基数特意**不抄 stars**：两个胶囊并排显示同一个数字，读起来像渲染 bug。也不会进「我的收藏」—— 收藏是「我要留着」，点赞是「我看过且认可」，混在一起收藏页会被灌水。

### 状态与持久化

- 初始集合在 `js/app.js` 的 `S` 里：`likePlug: new Set()`（和 `favPlug` 挨着）。
- 恢复两处都要改：`restoreState()` 里的 `Array.isArray(saved.likePlug)`，以及 `storage` 事件监听里的同一句（跨标签页同步）。
- `saveState()` 落盘键 `likePlug: Array.from(S.likePlug)`，存档键仍是 `dsh-forum-state-v1`。

### 交互与样式

- 点击委托 `act === 'ghlike'`：切 `S.likePlug` → `saveState()` → `render(false)` → toast「已点赞 / 已取消点赞」，`aria-pressed` 跟着变。
- 亮色「已赞」是品牌蓝底（`#eef6ff` / `#bcdcfb` / `#0b63a8`），和收藏的琥珀色分开，一眼能认出两个状态。
- 夜间单独一套：`#12293f` 底 / `#2b5b83` 边 / `#8fd0ff` 字。
- 拇指图标是 `ICON_PATHS.thumb`（20×20，stroke 1.6），点下去图标轻抬 1px，按下缩到 0.9；`prefers-reduced-motion` 关掉。

### 七条坑

1. **`av()` 把宽高写成行内 style**，媒体查询里必须 `width:36px!important` 才压得住 —— 第一次按普通规则写，手机上头像纹丝不动还是 44px。
2. **自己的头像没有跳转壳**：`js/app.js:388 av()` 只在 `uid !== S.account` 时加 `data-avuid` + `role=link`（那颗入口留给顶栏导航头像）。所以插件页里「自己」的那条要自己包 `<a class="gh-author-link">`，否则作者卡删掉之后自己的插件页上再没有进空间的入口。
3. **`.gh-side > section` 的顺序就是拼串顺序**（同 v42）：删卡要整段删除，别留空字符串占位，否则右栏多一张空卡的外边距。
4. **昵称与 ID 要塞进同一个 `<a>`**：头像上的 `data-avuid`（v40）已经是一个入口，名字再单独包一个链接，读屏会读成两个「进入空间」；把两行文字用同一个 `gh-author-tx` 链接包起来，`title` 里补全名，键盘只需 Tab 一次。
5. **这个文件有并行写入者**：本轮 `js/plugin-page.js` 在我读完之后被另一路改过（行号整体 +3），`tools.edit` 直接报 `file changed since it was read` —— 见到这条就重读、换锚点再改，别硬刚。
6. **同一份 CSS 里有两套 760 / 480 断点**：v38 基础层（`css/plugin-page.css:560`、`:621`）与 v39 皮肤层（`:1635`、`:1705`）各写了一份，同权重规则靠出现顺序决胜。新增的 ≤560 块第一次插在皮肤层 480 块中间，直接把那块切成两半（后面的 `.gh-stats` / `.gh-readme-body` 规则被卷进 560 段）；`tools.edit` 报「matched 2 times」也是同一个原因 —— 两套块内容一模一样。最终用 `lastIndexOf` 把 560 块放到文件最末，才对两套都生效。

## 收藏卡片整卡可点，撤掉「查看」胶囊（v42）

`#/favs` 的每一行原来是「缩略图 + 标题摘要 + 右侧动作列」，动作列里并排两颗按钮：**查看**（`data-act="favopen"`）和 **取消收藏**。v42 把「查看」删掉，整张卡片本身就是入口 —— 点缩略图、点标题、点空白，都直接跳到对应内容。

### 为什么用「铺层」而不是给卡片挂 role="button"

直觉做法是给 `.fav-item` 加 `role="button"` + `tabindex="0"`，但它里面还有一颗真按钮「取消收藏」——**可聚焦控件嵌套可聚焦控件**，读屏会把整张卡读成一个按钮、里面的按钮变成孤儿，键盘 Tab 也要多按一次。所以改成一张铺满卡片的透明 `<button class="fav-open">`：

```html
<div class="fav-item" role="listitem">
  <button class="fav-open" data-act="favopen" …aria-label="打开：…"></button>
  <div class="fav-thumb">…</div>
  <div class="fav-bd">…</div>
  <div class="fav-acts"><button class="fav-remove" data-act="unfav">取消收藏</button></div>
</div>
```

- `.fav-item{position:relative}`，`.fav-open{position:absolute;inset:0;z-index:1}` —— 铺层脱离网格流，不影响 `thumb bd acts` 三列布局。
- `.fav-acts{position:relative;z-index:2}` —— 动作列抬到铺层之上，点「取消收藏」命中的是它自己（事件委托取 `closest('[data-act]')`，最近的 `unfav` 胜出），不会顺手把卡片也打开。
- 铺层是真的 `<button>`：Tab 能停在卡片上，**Enter / 空格就是打开**（浏览器原生激活），不需要再写 keydown 分支；`:focus-visible` 给整卡描一圈 2px 品牌色内描边。
- 失效收藏（内容已被删）不生成铺层：卡片 `.is-missing`，点不动，只能取消收藏 —— 免得点了弹一句「已经不在了」。

### 撤掉的「查看」与留下的「取消收藏」

`.fav-acts` 现在只剩一颗「取消收藏」，CSS 里 `.fav-acts .btn{padding:4px 12px}` 与对应的 `:focus-visible` 选择器一并删掉（那是给「查看」用的）。≤760px 的 `.fav-acts{padding-right:46px}` 保留：它是给右下角固定的「回到顶部」圆钮让位的，和这次改动无关。

## 手机和电脑同时在线：登录设备列表（v46）

v17 定的是「单账号单会话」：同一账号在别处已经登录时，登录直接回 409，只有显式 takeover 才顶替。
这条规则本身没错 —— 它挡的是「两个浏览器同时用一个账号」—— 但它把「手机 + 电脑」也一并挡在了门外：
手机上刚登过，回家开电脑就被要求顶掉手机，等于每次换设备都要重新登一次。

v46 把「会话」从「每账号一条」改成「每账号每类设备一条」。**同一台设备**再登录仍然只保留一条
（重复登录还是要显式顶替），**手机与电脑互不影响**，各留各的。

### 1. 服务端：会话按设备分桶

`sessions` 表加一列 `device TEXT NOT NULL DEFAULT ''`（`server/src/schema.sql` 的 DDL 也同步了），
字面量只有 `pc` / `mobile` 两个，由 UA 推出来：

```js
const DEVICES = ['pc', 'mobile'];
const MOBILE_UA = /Android|iPhone|iPod|iPad|Windows Phone|HarmonyOS|Mobile|Tablet/i;
function deviceOf(ua) { return MOBILE_UA.test(String(ua || '')) ? 'mobile' : 'pc'; }
```

- `createSession()` 里 `replace` 的删除改成**按桶**：`deleteSessionsByUserDevice.run(user_id, device)`，
  索引也换成非唯一的 `idx_sessions_user_device(user_id, device)`。
- 登录只在**同桶**里判重：`liveSessionFor(row.id, device)` 命中才 409 `ALREADY_ONLINE`，
  带上 `device` 与 `label`（`电脑` / `手机`），前端据此把按钮写成「顶掉电脑上的登录」。
- 老库升级走 `auth.js` 顶部的幂等迁移 `migrateSessionsToMultiDevice()`：补列 → 删掉旧的
  `idx_sessions_one_per_user` → 按既有 UA 回填 `device` → 建新索引。

新端点（都要登录）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/auth/sessions` | 本账号的会话列表（最多两条），每行 `{ key, device, ua, ip, createdAt, expiresAt, current }` |
| POST | `/api/auth/sessions/revoke` | `{ key }` 退掉那一台（`key` 只是 sid 前 8 位），或 `{ others:true }` 退掉除当前之外的全部 |

`key` 用 sid 前 8 位而不是整条 sid：整条 sid 只在各自浏览器的 JWT 里，设置页只需要一个「指哪台」的把手，
不该把能拼会话的完整标识发给任何一端。

### 2. 前端：设置页多一块「登录设备」

`#/settings` 的「账号与安全」原来有两行（「会话」+「单账号单会话」），现在换成：

- **登录设备**：一行一台，📱 / 💻 + 「手机 / 电脑」+ 系统 · 浏览器（`uaShort()` 只留 `Windows · Chrome` 这一层，
  整串 UA 又长又挡视线）+ 登录时间；当前那台标绿「当前」，其余标灰「在线」并带一个「退出」按钮。
- **多端同时在线**：一句人话说明规则（手机和电脑各一条，同设备再登只顶自己）。
- 底部按钮多一个「退出其他设备」（只在真的有别的设备在线时出现，否则就是个按了没反应的按钮）。

列表是异步的：`render()` 画完帧调 `loadDevices(false)` 去问服务端，回来若还停在设置页就 `render(true)`。
`S.devicesFor` 记这份数据属于哪个 `sid` —— 换号之后旧列表立刻作废，不会把上一个人的手机型号摆给现任看。
失败时把错误挂在 `S.devicesErr` 上并给一行「重试」，**不在失败分支里再触发一次渲染**：否则
`render → loadDevices → 失败 → render` 会自己转圈打服务端。

登录框的 409 提示也改了：`authErrOf()` 把 `err.label` 透传出去，按钮从「顶掉那边的登录」变成
「顶掉电脑上的登录 / 顶掉手机上的登录」—— 用户看到「撞车了」时必须一眼知道要去哪台设备上退出。
窄屏（≤480）下这条提示会折成两行，`.auth-err .auth-link{margin-left:0}` 让链接跟着文字左对齐，
不然它会被 `margin-left:auto` 推到右边，像浮在句子外面。

旧文案里「一个账号，一台设备，一条会话」「每个账号最多一行会话」「一个账号一条会话」（第三方授权页）三句
都指向旧规则，一并改掉了 —— 规则改了而宣传语不动，是最容易让人以为站点坏了的地方。

### 坑

- **迁移不能写进 `schema.sql`**：schema 由 `db.js` 在 `auth.js` 之前整段 `db.exec`，而老库那时还没有
  `device` 列 —— 在 schema 里建 `(user_id, device)` 索引会让服务直接起不来：
  `SqliteError: no such column: device`。补列 / 回填 / 建索引必须按顺序写在 `auth.js` 顶部，
  且**整段迁移要在 `STMT` 之前**（`db.prepare` 是模块加载期执行的，索引不到列就当场抛）。
- **`created_at` 本来就是 Unix 秒**（`db.now()`），`sessionsForUser` 里再 `/1000` 会得到 1970 年的日期，
  前端还会一本正经地渲染成「1/22 01:59 登录」。前端 `* 1000` 的前提是接口回秒，两边只保留一处换算。
- **登录限流是 10 次 / 10 分钟（按 IP）**，自检脚本连着跑很容易撞 429：用 `takeover:true` 把登录次数压到两次；
  真要重置计数器就重启后端 —— 限流计数在内存里，会话行在 SQLite 里，重启不会把谁登出。
  这个 429 还会**伪装成「按钮没反应」**：点「顶掉…」之后页面纹丝不动、`/me` 还是 401，看着像前端没绑事件，
  实际是那一次请求被限流吃掉了。排查顺序是先看 `.local-server.log` 里有没有 `"code":"TOO_MANY","status":429`。
- **CDP 注入 cookie 有两个坑**：从 `Set-Cookie` 取值要先 `split(';')[0]` 再切 `=`，
  否则拿到的是 `eyJ…; Max-Age=604800`（`Network.setCookie` 报 `Sanitizing cookie failed`）；
  传参用 `{ name, value, url: 'http://127.0.0.1:8777/' }` 这种 url 形式最稳。
- **列表顺序与颜色的语义**：当前这台必须排第一（否则「我现在在哪」要往下找）；绿色只留给「当前」，
  其它设备用中性灰标签 —— 全绿会让「在线」和「生效」混成一个意思。

## 短信通道：三家可换，没备案也能先联调（v48）

站点要发真实验证码，绕不开「短信签名」这道审核 —— 而签名最常见的来源就是**已备案的网站**。
所以「备案没下来」不是「不能接短信」，而是「暂时拿不到网站类型的签名」。v48 把通道做成可替换的一层，
先把「发码」这件事从路由里摘出来，换供应商时只改环境变量。

### 通道适配层

`server/src/sms/index.js`（新文件，只依赖内置 `crypto` + `fetch`，**不引任何云 SDK**）：

| 导出 | 作用 |
| --- | --- |
| `provider()` | 读 `SMS_PROVIDER`，认 `tencent` / `aliyun` / `webhook` / `dev`，其余回 `none`；兼容老开关 `SMS_DEV=1` |
| `usable()` | provider 不是 `none` 且必需 env 齐全 —— 少一项就不假装能发 |
| `describe()` | `{provider, usable, missing, dev}`，排查「为什么没发出去」的第一现场 |
| `send({phone,code,ttl,scene})` | 成功回 `{delivered:true, channel, id}`；失败一律 **throw**（`SmsError` 带 `code/detail`） |

为什么让失败 throw 而不是回 `{ok:false}`：调用方只需要处理「没发出去」这一件事，
返回值里留一个 `ok` 字段，早晚会有人忘记看它。

三家的差别都关在文件里：

| provider | 签名方式 | 关键参数 |
| --- | --- | --- |
| `tencent` | TC3-HMAC-SHA256（日期→服务→`tc3_request` 逐级派生） | `SendSms` / `2021-01-11`；`TemplateParamSet` 要**两个**变量：验证码、有效分钟数 |
| `aliyun` | RPC 风格 HMAC-SHA1（参数排序 → 拼串 → base64） | `dysmsapi` / `2017-05-25`；`TemplateParam={"code":…}`，模板变量名必须是 `code` |
| `webhook` | HMAC-SHA256(`rawBody`, `SMS_WEBHOOK_SECRET`) 放 `X-SMS-Sign` | POST JSON `{phone,code,ttl,scene}`，2xx 即受理 |

超时 8s、**只对网络错误重试一次**；模板不存在 / 余额不足 / 号码黑名单这类业务错误不重试 ——
重试只会把同一条错误码收两遍，日志里还会多一条假的「发送失败」。

### 路由层怎么用

`server/src/routes/phone.js` 的 `/send` 现在是三段：

1. `dev` 通道：码回显在响应 `devCode` 与日志，`delivered:true`；
2. `usable()`：`await sms.send(...)`，**抛错就 `DELETE phone_codes` 回滚，再回 `502 SMS_FAILED`**；
3. 其余：只写日志，`delivered:false`，前端据此显示「通道还没接通，可以先跳过」。

回滚这条是有代价的决定：用户看到「发送失败」，本来还能用那条码继续试（码确实进了库），
但库里躺一条谁也收不到的码，等于给撞码白送 `CODE_TRIES`（5）次机会，而且「发失败却能验过」
这种状态没人能解释。宁可让他重点一次。

`/config` 多回一个 `provider`：出故障时一眼分清「通道没配」和「通道拒收」。

### 验收（`.shots/probe-sms48.mjs`：本地起假网关 127.0.0.1:3999）

| 场景 | 结果 |
| --- | --- |
| 配好 webhook | `/phone/config` → `{smsEnabled:true, provider:"webhook", devMode:false}` |
| 正常号发码 | `/send` 200，`delivered:true` `channel:"webhook"`；假网关收到 `{phone,code,ttl:300,scene:"verify"}` 且带 `X-SMS-Sign` |
| 错码 | `/verify` 400 `CODE_WRONG` |

### 没备案时的可选路径

| 路径 | 能发真实号码 | 代价 |
| --- | --- | --- |
| `SMS_PROVIDER=dev` | 否（码回显） | 只能本机/CI 联调 |
| 腾讯云「测试专用签名 + 测试模板」 | 只发**白名单号码**（开发者本人 + 少量测试号） | 上线前必须换正式签名 |
| 阿里云「测试专用签名」 | 同上，需报备接收号码 | 同上 |
| 签名来源用**企业主体**（营业执照 / 商标） | 是 | 不需要域名备案，但要企业资质，签名须为企业全称或简称 |
| 签名来源用**已认证公众号 / 已上架小程序·App** | 是 | 需要公众号认证（300 元/年）或应用市场上架 |
| `webhook` 接聚合商（云片 / 容联 / SUBMAIL…） | 看服务商 | 免备案通道近年被运营商收紧，送达率与稳定性不受控，通道被关会直接影响登录 |
| 国际短信 + 境外号码 | 是（仅境外号） | 国内号码不适用，成本高 |

本站的手机号认证**不是闸门**（`#/verify` 有「跳过认证，先进站」出口，也没有路由挂
`requirePhone`），所以备案期间可以先上线，等签名过审再把 `SMS_PROVIDER` 填上即可 ——
前端会自动从「通道没接通」切成「验证码已发送」，不需要改代码。

### 坑

- **模板变量个数必须与服务商后台一致**：腾讯云模板是 `{1}` 验证码 + `{2}` 分钟数，只传一个会回
  `InvalidParameterValue.TemplateParameterLengthMismatch`；阿里云变量名写死 `code`，模板里写
  `${code}` 才行。
- **`.env` 不覆盖已有环境变量**（`server/src/index.js` 只在 `process.env[k] === undefined` 时写入）：
  联调时用 `$env:SMS_PROVIDER='webhook'` 起的进程会盖过 `.env`，改完 `.env` 没生效先查这个。
- **探针里 `better-sqlite3` 必须从 `server/` 解析**：`.shots/*.mjs` 在仓库根跑，`import 'better-sqlite3'`
  会 `ERR_MODULE_NOT_FOUND`，要用 `createRequire('…/server/package.json')` 再 `require`。
- **验证码时间单位**：`phone_codes.created_at` 与 `users.phone_at` 都是 **Unix 秒**（`db.now()` 已除过），
  再除 1000 会渲染成 1970 年 —— v46 的会话列表踩过一次。
