# 鲸域 · 动静分离部署手册

## 一、架构

```
                     ┌──────────────┐
   www.example.com ──┤  CDN 加速    ├──► COS（静态：html/css/js）
                     └──────────────┘        同地域内网回源，免回源流量费

   api.example.com ──────────────────────► 云服务器 127.0.0.1:3000（API）
                                            MySQL / SQLite + Redis
```

**核心思路**：静态资源一点不占服务器带宽，服务器只处理 JSON 请求。

这个站 gzip 后首屏只有 **92.3 KB**，且没有任何图片和字体（图标都是内联 SVG）。
所以 CDN 的流量成本几乎可以忽略，而省下的服务器带宽是实打实的钱。

## 二、成本

| 项目 | 规格 | 月成本 |
|---|---|---|
| 轻量应用服务器 | 2核4G / 6M 带宽 / 80G SSD | ¥80–120 |
| COS 存储 | 10 GB 标准存储 | ¥1.2 |
| CDN 流量包 | 100 GB / 月 | ¥12–18 |
| 域名 | .com（年付摊月） | ¥5 |
| SSL 证书 | 腾讯云免费证书 | ¥0 |
| **合计** | | **约 ¥100–145** |

**对比不分离**：要扛同样的并发，静态资源全走服务器带宽需要 12M 以上的套餐，
2核4G/6M 升到 4核8G/12M 大约多 ¥100/月。而 CDN 100GB 只要 ¥15。

> 结论：动静分离每月省约 ¥85，同时抗突发能力强一个数量级。
> 价格随活动浮动，以腾讯云官网为准。

**起步省钱技巧**：数据库先用 SQLite，省掉 MySQL 那 500MB 内存和单独进程。
日活过千再迁 MySQL，迁移成本不高。

## 三、部署步骤

### 1. 构建

```bash
node deploy/build.mjs
```

产物在 `dist/`，会给 css/js 自动加内容哈希：

```
dist/
├── index.html
└── assets/
    ├── app.fa297f11.css
    ├── brand.ed7cca3b.js
    ├── data.59475a5e.js
    └── app.19edbbb7.js
```

**为什么必须加哈希**：CDN 上给 js/css 配一年缓存后，如果文件名不变，
你更新了内容用户也永远拿不到新版本。加哈希后文件名随内容变，缓存自然失效，
不用手动刷 CDN。

### 2. 上传到 COS

```bash
# 安装 coscli 后配置密钥：coscli config add -b <bucket> -r <region>
coscli cp dist/ cos://jingyu-1300000000/ -r
```

COS 设置：
- 存储桶权限：**私有读写**（由 CDN 回源鉴权，不要开公有读，防止被人直接刷流量）
- 地域：与 CDN 节点同地域，回源走内网，**免回源流量费**
- 防盗链：Referer 白名单填 `www.example.com`

### 3. 配置 CDN

| 路径 | 缓存时间 | 说明 |
|---|---|---|
| `/assets/*` | **365 天** | 带哈希，永久缓存，命中率 99%+ |
| `/index.html` | **60 秒** | 入口文件，靠短缓存更新 |
| `/`（默认） | 60 秒 | |

其他必须开的开关：
- **HTTPS**：申请免费证书
- **Brotli / gzip**：比 gzip 再省 15–20%，首屏能从 92.3 KB 压到约 78 KB
- **HTTP/2**：多路复用，5 个文件并发拉取
- **回源协议**：HTTPS
- **缓存键**：忽略 URL 参数，提高命中率

### 4. 服务器

```bash
# 上传 nginx.conf 到 /etc/nginx/conf.d/jingyu.conf，改掉 example.com
nginx -t && systemctl reload nginx
```

服务器只跑 API，`nginx.conf` 里已经配好：
- API 反向代理 + WebSocket 升级头（聊天模块用）
- CORS 只放行前端域名
- 上传体积限制 8MB
- 安全响应头

### 5. DNS

| 记录 | 类型 | 值 |
|---|---|---|
| `www` | CNAME | CDN 分配的加速域名 |
| `api` | A | 云服务器公网 IP |

**备案**：国内服务器和 CDN 都要求域名已备案。UGC 社群备案需要额外提交
内容审核制度、实名认证方案，审核周期比普通网站长，提前准备。

## 四、图片与动图

### 4.1 这块才是真正花钱的地方

纯文字动态时代，CDN 流量可以忽略。一旦用户能发图片和动图，
**图片会占全站流量的 95% 以上**，前面「CDN 几乎免费」的结论就不再成立。

以 1000 日活、每人每天看 30 张图为例：

| 方案 | 单次传输 | 月流量 | 月成本 |
|---|---|---|---|
| 原图直出 | 1.5 MB | 1350 GB | ¥283 |
| 缩略图 WebP | 80 KB | 72 GB | ¥15 |
| 缩略图 + 点击看原图 | 混合 | 207 GB | ¥43 |

**缩略图能省 92% 的流量。** 这是图片方案里最重要的一件事，
比选哪家云厂商重要得多。存储反而不贵：年增 144 GB，摊下来每月不到 ¥10。

### 4.2 上传必须直传，不能中转

```
✗ 错误：浏览器 → 服务器 → COS
   一张 2 MB 图走 6M 带宽要 2.7 秒，10 个人同时传就堵死

✓ 正确：浏览器 →（预签名 URL）→ COS 直传
   服务器只签发凭证，完全不碰图片数据
```

流程：

1. 前端 `POST /api/upload/sign` 拿预签名 URL
2. 前端 `PUT` 直传到 COS
3. 前端发帖时只带 COS key
4. 展示时拼 CDN 地址

服务器全程只处理几百字节的 JSON，6M 带宽绰绰有余。
**这一条是整个图片方案的基础**，走中转的话前面动静分离省下的带宽全白费。

### 4.3 展示用 COS 图片样式

不要在前端随手拼处理参数，用 COS 的**图片样式**固化：

```
https://img.example.com/u/2026/10/abc123.jpg?style=thumb
```

| 样式名 | 参数 | 用途 |
|---|---|---|
| `thumb` | `imageMogr2/thumbnail/750x/format/webp/quality/85` | 动态流 |
| `thumb-sm` | `imageMogr2/thumbnail/320x/format/webp/quality/80` | 列表小图 |
| `origin` | 不处理 | 点开看大图 |

URL 固定，CDN 每个图每个样式只缓存一份，命中率可预测。
如果在 URL 里动态拼参数，缓存会碎片化，成本翻好几倍。

### 4.4 动图专项

GIF 是流量的最大杀手——一张 3–5 MB 的 GIF，比十张普通图片还重。

| 措施 | 效果 |
|---|---|
| GIF 转 WebP 动图 | 体积降 60–70% |
| 动图缩到 800px | 再降 50% |
| 单张 ≤ 5 MB、时长 ≤ 10 秒 | 挡住极端情况 |
| 超阈值转视频 | 再降 10 倍（后期做） |

一张 5 MB 的 GIF 转成 800px WebP 动图后约 400 KB，**省 92%**。

兼容性：WebP 动图在 iOS 14+ / Chrome 32+ 全部支持，覆盖率 95% 以上，可以放心用。
**不要用 AVIF 动图**，Safari 支持还不完整。

### 4.5 前端先压一遍

上传前在浏览器里压缩，比在服务器压便宜得多：

- 静态图：长边限制 1920px，质量 0.85，平均从 4 MB 压到 1.5 MB
- 动图：不改画面，只限制尺寸和文件大小

原图小了，上传更快、存储更省、回源处理压力也更小。

### 4.6 两个容易踩的坑

**防盗链和分享冲突**：图片 CDN 开 Referer 防盗链后，从微信/QQ 分享出去的
链接 Referer 为空，会直接 403。要么允许空 Referer，要么改用签名 URL。

**缓存键必须包含 query**：图片样式参数在 query string 里，CDN 缓存键
如果不含 query，`thumb` 和 `origin` 会互相覆盖，用户点开大图看到缩略图。

## 五、验收清单

- [ ] `curl -I https://www.example.com/assets/app.xxxx.css` 返回 `cache-control: public, max-age=31536000, immutable`
- [ ] `curl -I https://www.example.com/index.html` 返回 `cache-control: no-cache` 或 `max-age=60`
- [ ] 响应头有 `content-encoding: br` 或 `gzip`
- [ ] 连续刷新两次，第二次静态资源全部命中 CDN 缓存（`x-cache-lookup: Hit`）
- [ ] `curl -I https://api.example.com/healthz` 返回 200
- [ ] 直接访问 COS 源站域名返回 403（确认私有读生效）
- [ ] 上传一张 JPG，`?style=thumb` 返回 `content-type: image/webp`
- [ ] 上传一张 GIF，返回的是 WebP 动图且体积降 80% 以上
- [ ] 上传时看服务器带宽监控，确认流量没走服务器（直传生效）

## 六、后续演进

| 阶段 | 变化 |
|---|---|
| 日活 < 500 | 现在这套就够，单机 + SQLite |
| 日活 500–2000 | SQLite 换 MySQL，加 Redis 缓存热帖 |
| 日活 2000+ | 数据库独立上云数据库，加负载均衡，CDN 全站加速 |

静态层几乎不用动——COS + CDN 天然能扛住十倍流量，这就是动静分离最大的好处。
