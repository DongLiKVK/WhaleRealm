# 鲸域 whalerealm.top · 功能完备性评估（产品视角）

对象：线上 https://whalerealm.top 与本地源码 D:/DSH program/WhaleRealm。两类目标用户：DSH 开发者（找插件、看更新、提问交流、买会员）与站长/管理员（上架插件、审内容、发奖励、对账开通会员）。判断标准：核心任务能否在站内闭环。

## 一、核心发现

| 编号 | 问题 | 严重级别 | 证据 | 影响 |
|---|---|---|---|---|
| P1 | 插件库线上 0 条，且无创建插件的后端，「+ 发布插件」只写内存 | 高 | GET https://whalerealm.top/api/plugins → {"items":[]}；js/app.js:6609-6613 仅置 stage='review' 后 toast；server/src/routes/forums.js:131、196 只有 GET 与 claim，无 POST /api/plugins | 第一核心场景「找插件」零内容且永不自增长，社群失去存在理由 |
| P2 | 社群是演示空壳：服务端 0 版块，前端仍渲染 16 条演示帖，发帖必 404 | 高 | GET /api/forums → {"items":[]}；js/api.js:340 仅 cats.length 非空才替换演示分类；server/src/routes/forums.js:75-77 版块不存在直接 404 | 用户看到 128 回复/18.4k 浏览的假繁荣，一发帖就失败，信任与留存双杀 |
| P3 | 消息中心对真实账号恒空，全站不产生通知 | 高 | js/app.js:677-681 真实账号直接 return []；server/src/routes 18 个文件无 notifications 路由 | 点赞/回复/@ 无回流，互动缺第二次触达，社群形不成回路 |
| P4 | 审核链路是装饰：动态不过滤 status，后台隐藏不生效 | 中 | server/src/routes/posts.js:61-62 查询无 WHERE status；posts.js:9-39 shapePost 不返回 status；js/app.js:2153 却承诺「审核中只有你自己看得见」 | 站长以为能下架，内容仍在信息流；违规处理只能改库 |
| P5 | 后台缺运营半边天 | 中 | admin/js 仅 page-dashboard/posts/users/rewards/roles/logs；无插件审核、版块分类、评论、举报、通知管理 | 插件上架与社区治理要回数据库手改，运营不可持续 |
| P6 | 会员只能人工对账 | 中 | js/membership.js:619 offline=afdian/manual；643-668 跳爱发电后回站登记订单号人工开通；691 在线通道二维码为占位 | 付费转化依赖站长在线，到账到开通有小时级延迟 |

| P9 | 线上可见计算 bug | 低 | js/app.js:2487 Math.round(cnt.pack / plugins.length * 100) 除零；实测市场页显示「登记了包信息的条目占 NaN%」 | 首屏出现 NaN，显得未完工 |

## 二、缺失/半成品功能清单

需求覆盖度（核心任务 → 支撑功能 → 是否可用）：

| 核心任务 | 支撑功能 | 是否可用 |
|---|---|---|
| 找插件 | 条目库 / 23 分类 / 搜索 / 下载 | 否：0 条且无创建入口（P1、P8） |
| 看更新 | 动态流 / 插件更新日志 | 部分：仅 1 条真实动态（/api/feed） |
| 交流 | 版块发帖 / 回复 / 私信 | 否：发帖 404（P2）；私信 WS 可落库（server/src/routes/chat.js:80-105）但无通知 |
| 买会员 | 四档价目 / 支付 / 开通 | 部分：仅人工对账（P6） |
| 管内容 | 后台审核 / 举报 / 通知 | 否：无插件与举报管理（P5、P4） |

有入口没链路：
- 插件发布：市场页「+ 发布插件」表单完整（live-market.png），提交只 toast（js/app.js:6609-6613），无 POST 接口。
- 版块：左栏 16 个分类可点，服务端 forums 表为空，发帖必 404（server/src/routes/forums.js:75-77）。
- 举报：四类举报 UI 齐全（js/app.js:2788-2798），提交只提示「演示站不真的发出去」（js/app.js:6321），无落库。
- 关注/收藏：js/app.js:7617 只切换本地 S.follow，无接口，刷新即失效。

有内容没入口 / 文档与实现相反：
- 手机验证：前端已下线并重定向（js/app.js:6012-6013），README.md:230 仍称其为「闸门放行的最后一步」。
- 插件页版本/议题/贡献：均为演示数据，不请求 GitHub API（docs/plugin-pages-audit.md:164-176）。
- 私信自动回复：README.md:421 的 DM_AUTO 是本地定时器，不是真人。

半成品与低价值重投入：
- 半成品：在线支付通道（js/membership.js:691 占位）、审核五态（有接口无生效路径）、草稿（仅本地 js/app.js:82）。
- 重投入低价值：头像框/皮肤/装饰（js/avatar-frame.js、赞助头像框）、AI 排行整页静态榜单（js/rank.js:496「本站为演示站点」），以及 28 插件/16 帖/10 通知的演示数据本身（js/data.js）。

冷启动：线上真实内容 1 条（/api/feed），演示数据占比接近 100%（插件 28:0、帖 16:0、通知 10:0），首屏靠演示数字撑门面。

## 三、改进建议（按投入产出排序）

1. 播种版块：把 js/data.js 的 16 个分类写进 forums 表，或让前端分类只取服务端，先修「发帖必 404」。
2. 补 POST /api/plugins 与审核态，pubsubmit 改真调用，让插件库能自增长。
3. 首屏去假：386/1.2k/演示计数换成真实统计，宁可显示 0。
4. 加 notifications 表并在点赞/回复/@ 时写入，消息中心读真实数据。
5. 市场搜索接 API.plugins(q)，把 smartSearch 改成服务端搜索。
6. 举报落库 + admin 举报页（复用 page-rewards.js 骨架）。
7. admin 增插件审核页（复制 page-posts.js 骨架），先覆盖上架与下架。
8. 会员接一条真实在线支付，或做自动对账表减少人工。
9. 修 NaN%：js/app.js:2487 加 plugins.length 守卫。
