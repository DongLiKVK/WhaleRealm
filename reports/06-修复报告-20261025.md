## 三、逐条修复对照

### H1 插件页白屏（崩溃）→ 已修
- **根因**：`/api/plugins` 返回空时前端仍把空数组替换进去 → `pluginOf()` 回落 `plugins[0]` 得 `undefined` → `userOf(p.author)` 抛错 → `pageHTML` 无 try/catch，整页只剩骨架。
- **改法**：`pluginOf()` 不再回落；`entryPage` 先判空给「没有找到这个插件条目」空态；`pageHTML` 包 try/catch + `pageCrash()` 兜底卡（带 route 与错误文本）。
- **复验**：`#/plugin/p1` 渲染真实条目页（作者 林深见鹿 @s1 · dsh-blender-plugin）；`#/plugin/p29`（不存在）落到空态而非崩溃；7 条路由批量渲染 `crash=false`。

### H2 社群空壳（演示数据赖着不走）→ 已修
- **根因**：前端 `if (cats.length)` 保护导致后端空数组不清本地演示数据；后端 `seed.js` 以「posts 有行」为由整体跳过，生产那 2 条 hello world 让版块/插件永远补不上。
- **改法**：前端无条件替换；seed 改为「结构数据 upsert + 内容数据空表才灌」。
- **复验**：模拟生产空壳库跑 seed → 版块 0→14、插件 0→28、posts 保持 2；连跑两次结果一致（幂等）。

### H3 审核状态不生效（草稿/待审内容照样公开）→ 已修
- **根因**：`posts.js` 的 feed、详情、评论三处查询完全没有 `status` 条件。
- **改法**：按表结构探测生成 `ONLY_PUBLISHED`，feed/详情/评论全部带过滤；详情对「非 published 且非作者且非管理员」返回 404。
- **复验**：接口回归通过；管理员在后台改状态后前台即时消失（同一 SQL 条件）。

### H4 私信不可用（404 + 假自动回复）→ 已修
- **根因**：`index.js` 只在根路径注册了一次 chat 路由，`/api/messages/*` 全 404；前端 `dmSend` 只写内存，1.2 秒后伪造「收到，我看一下」。
- **改法**：chat 双注册；新增会话列表与发信接口；前端 `dmSend` 调真接口，失败标红并 toast，只有演示账号（u1…）保留自动回复。
- **复验（CDP 真浏览器）**：阿离 → 林深见鹿 发送成功，服务端 `messages` 落库 `{id:2, from:2, to:1}`；刷新后会话列表仍在，历史消息保留。

### H5 多处伪实现（楼层回复/留言/关注/收藏/删除）→ 部分修（楼层回复已真）
- **改法**：新增 `thread_replies` 表与回帖接口，前端楼层回复改为「本地先显 → 服务端落库 → 用服务端 item 替换临时楼层」。
- **复验**：CDP 点「回复」→ 服务端楼层 1→2、`threads.replies` 129→130，页面楼层导航 2→3。
- **未修**：空间留言、关注、收藏、动态删除仍为本地实现（见「未修项」）。

### H6 插件治理（非作者恒 501、上传只改内存、包信息伪造）→ 部分修（发布已真）
- **改法**：新增 `POST /api/plugins`（包名正则、重复 409、默认 tier/source/claimed），前端发布表单接真接口，成功后同步列表并跳到新条目页。
- **复验**：`POST /api/plugins` 200 落库（id 57，作者林深见鹿）；重复包名 409 `PKG_TAKEN`；`#/plugin/p57` 渲染出这条新条目。
- **未修**：版本上传（`/releases`）与包信息登记仍为内存态。

### H8 支付闭环缺失（report-paid 只写备注、无 webhook/对账）→ 未修（需真实支付通道与回调域名）
### H9 会员权益缺额度/称号/工单 → 未修（属产品设计缺口，非缺陷）

## 四、未修项与原因

| 编号 | 项 | 为什么这次不动 |
| --- | --- | --- |
| H7 | 改密 / 找回密码 / 邮箱验证 | 需要邮件通道（SMTP 或第三方）与令牌表设计，属于一个独立迭代；直接加接口会做出「点了没反应」的第二处伪实现 |
| H8 | 支付回调与对账 | 需要真实商户号、回调域名与验签密钥；本地只能写假 webhook，反而更难维护 |
| H9 | 会员额度/称号/工单 | 设计文档自述「未实现」，属于功能缺口而非 bug，需产品先定权益口径 |
| H10 | 赞助后台入口 | 入口位置（顶栏/我的空间/仅管理员可见）需要产品决策，先不擅自加 |
| M4 | 后台权限双轨（isAdmin vs requirePermission） | 改动会影响现有管理员可用性，建议单独一轮做权限矩阵回归 |
| M7 | feed 固定 30 条无分页 | 需要前端无限滚动或分页器，改动面大于本次 P0 |
| M15 | 积分不可见 | 需在 `publicUser` 增字段并同步前端展示，牵涉隐私口径 |
| M16 | 无退款入口但文案承诺 7 天 | 属运营流程，需先有退款审批动作 |
| L2' | 页脚三个 `javascript:;` 死链（关于社群/插件规范/反馈与建议） | 没有对应页面，新增内容页超出修复范围；已记录待补 |

## 五、上线注意（部署顺序）

1. **先跑迁移**：`thread_replies` 是 `CREATE TABLE IF NOT EXISTS`，随服务启动自动建；`posts.status` 仍由 `server/src/admin-db.js` 的 ALTER 补列，顺序不变。
2. **再跑种子**：`cd server && node scripts/seed.js`（现在是幂等 upsert，可安全在生产重跑，会把 14 个版块与 28 个插件补齐；已有 2 条动态不会被覆盖）。
3. **验证三条链路**：`GET /api/messages` 未登录应 401；`GET /api/forums/notice/threads/1` 应 200 且带楼层；`POST /api/plugins` 用管理员账号试发一条再删。
4. **前端发布**：`js/app.js`、`js/api.js` 需按 `deploy/build.mjs` 重新打包（线上走 `assets/app.<hash>.js`），并确认 `index.html` 引用同步更新。
