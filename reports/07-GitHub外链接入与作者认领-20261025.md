### 2. 字段映射：外链条目长什么样

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `tier` | `link` | 只挂外链，本站不存包 |
| `source` | `none` | 不是作者上传，也不是镜像 |
| `claimed` | `0` | 未认领 |
| `mirror` | `off` | 不镜像 |
| `freshness` | `none` | 不做新鲜度校验 |
| `ver` | `''` | 不编造版本号；前端显示「外链」而不是裸 `v` |
| `file_*` | NULL | 没有安装包、大小与 sha256 |
| `repo` | 真实 GitHub URL | 条目页主按钮指向这里 |
| `why` | 「作者还没来鲸域认领：这里只挂 GitHub 外链…」 | 条目页原样展示 |
| `author_id` | 占位账号「鲸域索引」（`index@whalerealm.top`，id=10） | 作者认领后过户给本人 |

导入器是**幂等**的：按 `slug` upsert，且只更新 `claimed=0 AND tier='link'` 的行 —— 作者认领之后脚本不会再把手改回去。生产实测第二次运行输出「新增 0 · 更新 56」。

### 3. 认领链路（真校验，不是提示语）

1. 作者用鲸域账号打开 `#/claim/p<id>`，页面调用 `POST /api/plugins/:id/claim` 领一个 32 位十六进制挑战串（24 小时有效，未验证前复用同一个串）。
2. 作者把串写进仓库 `README`（或提一个 Issue，标题/正文含该串）。
3. 页面点「我已添加，开始验证」→ `POST /api/plugins/:id/claim/verify`。
4. 服务端 `server/src/claim-verify.js` 真的去读仓库原文：先试 `raw.githubusercontent.com` 的 6 种 README 文件名，读不到再走 Contents API；Issue 走 `/issues?state=all`。命中则事务内把 `author_id` 改成认领者、`claimed=1`、`source='author'`、`why=''`，并在 `plugin_claims.verified_at` 留痕。
5. 已被别人认领 → 409 `CLAIMED_BY_OTHER`；串没写进仓库 → 400 `TOKEN_NOT_FOUND`；GitHub 限流 → 429 `RATE_LIMITED`；网络不通 → 502 `NETWORK`。

新增表 `plugin_claims`（`plugin_id, user_id, token, method, created_at, verified_at`，token 唯一索引）。

### 4. 前端呈现

- `js/app.js`：市场卡片/条目页不再出现「v + 空版本号」；今日更新数改成按 `_at` 现算，不再写死「386 条」；插件渲染加错误边界。
- `js/plugin-page.js`：**外链条目走独立面板**，只显示条目信息（仓库、分类、Star、许可证、认领状态）、真实仓库按钮与认领入口；不再为未认领的外链条目编造提交记录、议题、发布说明和 `pnpm dsh add` 安装命令。认领通过后自动回到完整仓库视图。
- `js/api.js`：新增 `claimChallenge` / `claimVerify`。

## 三、复验结果（生产实测）

- `GET /api/plugins` → 56 条；`tier=link` 56、`claimed` 0、`file=null`、作者统一「鲸域索引」、`repo` 指向真实仓库。
- `POST /api/plugins/1/claim` 未登录 → 401 `NOT_AUTHED`。
- 描述截断落在词/句边界并补省略号（生产 16/56 条超长描述被截，其余原样）。
- 市场页（无头 Chrome 读线上）：无崩溃、无 `NaN`、无裸 `v`，显示「共 56 个条目 · 已登记包 0 个 · 已认领 0 个」「登记了包信息的条目占 0%，文件都在作者仓库」。
- 条目页 `#/plugin/p2`：显示 ↗ 外链 / 未认领 / MIT / Star 4450 / 仓库 liustack·modlens，无假提交、无假议题（外链条目走独立面板，认领后才回到完整仓库视图）。
- 认领页 `#/claim/p1` 未登录 → 跳 `#/login`，提示「请先登录：认领条目需要用账号身份进入」。
- 本地端到端（真浏览器 CDP + 本地 GitHub 桩）：拿到 32 位真验证串 → 写入桩 README → 点验证 → 页面变「✓ 仓库已认证」，`/api/plugins` 里该条目 `claimed=true`、`why=""`；换第二个账号抢同一条目 → 409 `CLAIMED_BY_OTHER`。

单元测试：`tmp/claim-verify.test.mjs` 11 条全通过（5 种仓库写法、README 命中/未命中、Issue 命中、坏串、无仓库、gist 不支持）。

## 四、没做的（明确边界）

1. **Gist 认领方式未开放**：读 Gist 需要 GitHub OAuth token，站点目前没有 GitHub 登录授权，前端已在该页签标注「未开放（需 GitHub OAuth）」。
2. **认领后的版本号与许可证仍以作者仓库为准**：站点不抓取、不解析作者仓库，作者认领后可以自己在条目里补版本与包信息。
3. **不做仓库内容镜像与定时同步**：Star 数是收录当时的快照，不随 GitHub 实时变化。
4. **会员/支付/改密等旧缺陷不在本次范围**：见 `reports/00` 与 `reports/06`。

## 六、作者认领之后会发生什么

1. 条目页作者从「鲸域索引」变成作者本人，`source=author`、`why` 清空，页面从「外链面板」切到完整条目视图。
2. 作者可以补版本号、上传安装包（走已有的上传接口），也可以维护条目的说明与截图。
3. 导入脚本不会再覆盖这个条目（`claimed=0 AND tier='link'` 才更新）。
